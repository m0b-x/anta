# The overview's saved views (docs/calendar-overview-list-roadmap.md §3.12,
# slice 9c, D17): List through its mode chip on Last 90 days, the bar's
# bookmarks button, the current list saved under a name through the name
# dialog, the period moved to This year, the view applied from its row —
# which closes the sheet and puts the list back on Last 90 days — then the
# view renamed and deleted through its ⋮. Leaves the overview on Year and
# This year, as the seed has it, with no saved view.
# - A view's row, ⋮ and handle ids carry its UUID, which a flow cannot know:
#   the row is tapped by its name and the ⋮ by its tooltip, "Saved view
#   options", which is unique while one view exists.
# - The name dialog opens with the period's words selected; `type` replaces
#   them. "Save" alone is ambiguous here ("Saved views", "Save the current
#   list"), so the dialog is waited on and saved by its ids.
# - Applying closes the sheet; the nav's title then reads "Last 90 days" again
#   and the bar button is selected (not readable as text: the sheet's ✓ on
#   the row is what a reopen shows).
# - The save's message, Saved as "Ninety days", can still be up when the
#   sheet reopens, and a tap on "Ninety days" then matches it as well as the
#   row: the flow waits for "Saved as" to go first.
# - The delete confirmation's button is "Delete"; the menu that also says
#   "Delete" has closed by then.
