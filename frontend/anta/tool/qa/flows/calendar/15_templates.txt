# The template form (docs/calendar-language-tier-2-roadmap.md §3.5–§3.6)
# through the calendar's ⋮, Calendar settings and the Event templates page:
# the seeded "Leg day" opens the form on its ids; the name is changed, Repeat,
# Icon & color and the description are each opened and cancelled, ✕ asks,
# Keep editing stays, ✕ and Discard leave the template as it was. Then a new
# template is named, saved, listed and deleted through the page, so the
# fixture's one template is all that is left.
# - Scrolling the settings page while the semantics tree is on makes the
#   Android engine log `E/AccessibilityBridge: transform has not been
#   initialized` (debug builds, seen 2026-10-02): the `errors` step at the end
#   prints that line from the run log, the agent's own buffer stays clean.
# - The template variant of the Repeat sheet is read from what it leaves
#   out — the "Public holidays only" kind and the Ends row, whose value would
#   be "Never" ("Ends" itself is inside "Weekends") — and from the hint that
#   names no date.
# - Count occurrences is off in the seed, so the count-style chips are not
#   on this form; Starts, Ends and its ✕ are there because it is timed.
# - The page's create button (id:templates-create) is out of the tree while
#   a form is up, so waiting for it is waiting for the page; after the new
#   form's Save the page is waited for by id:template-save gone.
# - A template's delete is keyed by its row's position (a template made here
#   has an id no step can spell): the new template is the second row, and
#   the dialog names what it is about to delete before the confirm.
tap id:calendar-more
wait id:calendar-settings-open
tap id:calendar-settings-open
wait id:calendar-add-event --gone
scroll-to id:calendar-event-templates-open
tap id:calendar-event-templates-open
