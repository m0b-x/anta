# The template form (docs/calendar-language-tier-2-roadmap.md §3.5–§3.6)
# through the calendar's ⋮, Calendar settings and the Event templates page:
# the seeded "Leg day" opens the form on its ids; the name is changed, Repeat,
# Icon & color and the description are each opened and cancelled, ✕ asks,
# Keep editing stays, ✕ and Discard leave the template as it was. Then a new
# template is named, saved, listed and deleted through the page, so the
# fixture's one template is all that is left.
# - The settings page's rows carry no ids; "Event templates" is its row's
#   own first line. Scrolling that page while the semantics tree is on makes
#   the Android engine log `E/AccessibilityBridge: transform has not been
#   initialized` (debug builds, seen 2026-10-02): the `errors` step at the end
#   prints that line from the run log, the agent's own buffer stays clean.
# - The Repeat sheet has no id on its ✕; nothing else is in the tree while it
#   is up, so its tooltip "Cancel" names it. The template variant is read
#   from what it leaves out — the "Public holidays only" kind and the Ends
#   row, whose value would be "Never" ("Ends" itself is inside "Weekends") —
#   and from the hint that names no date.
# - Count occurrences is off in the seed, so the count-style chips are not
#   on this form; Starts, Ends and its ✕ are there because it is timed.
# - "New template" is the page's button and the new form's title: the page
#   is waited for by the button only while no new form is up, and by
#   id:template-save gone after the new form's Save.
# - The page's delete buttons share a tooltip; the new template is the last
#   row, and the dialog names what it is about to delete before the confirm.
