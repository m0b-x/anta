# The alert sheet's second caller (docs/calendar-language-tier-2-roadmap.md
# §3.2, §4.1): Calendar settings' two default-alert rows. The timed default
# opens the sheet without the Alarm sound row and without Remove after it
# rings, takes a preset from the When menu and is read back on the settings
# row as "Tier · offset"; the all-day default shows Time of day and is
# confirmed as it opened. Both are then set back to none through the sheet's
# Remove alert, which here means "no default" — the fixture ships both as
# none, and a default left behind would seed an alert into every event the
# other flows create.
# - The settings rows carry no ids: each is named by its own first line and
#   read by its last one, the tier and the timing or "No alert".
# - The all-day row's time follows the phone's clock, so only "On the day"
#   is read, never the hour.
# - A default is no event: the sheet offers Remove alert even while the
#   default is none, and Done on an untouched sheet writes the draft.
# - Scrolling this page with the semantics tree on makes the Android engine
#   log `E/AccessibilityBridge: transform has not been initialized` (see
#   15_templates.txt); the agent's own buffer stays clean.
