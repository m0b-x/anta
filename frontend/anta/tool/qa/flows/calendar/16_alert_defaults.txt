# The alert sheet's second caller (docs/calendar-language-tier-2-roadmap.md
# §3.2, §4.1): the two default-alert rows, on Alert settings since D5 of
# docs/settings-rework-roadmap.md, reached from Calendar settings' one
# Alerts row (the page's last) as a user coming from the calendar would;
# back lands on Calendar settings, then on the calendar. The timed default
# opens the sheet without the Alarm sound row and without Remove after it
# rings, takes a preset from the When menu and is read back on the settings
# row as "Tier · offset"; the all-day default shows Time of day, and Done on
# it untouched leaves the row at "No alert" (N148) — reopened, a tier tap
# makes it a choice and Done writes it. Both are then set back to none
# through the sheet's "No default alert" — the fixture ships both as none,
# and a default left behind would seed an alert into every event the other
# flows create.
# - The two settings rows are tapped by id and read by their last line, the
#   tier and the timing or "No alert".
# - The all-day row's time follows the phone's clock, so only "On the day"
#   is read, never the hour.
# - The Defaults section is Alert settings' first, so both rows are on
#   screen when the page opens; only Calendar settings is scrolled.
# - A default is no event: the sheet offers "No default alert" even while
#   the default is none, and Done on an untouched sheet writes nothing.
# - Scrolling this page with the semantics tree on makes the Android engine
#   log `E/AccessibilityBridge: transform has not been initialized` (see
#   15_templates.txt); the agent's own buffer stays clean.
