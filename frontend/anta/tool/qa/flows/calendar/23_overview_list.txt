# The overview's list (docs/calendar-overview-list-roadmap.md §3.2–§3.6,
# slice 3b): List through its mode chip, the Period menu from the nav's
# title (§3.13) and Custom range… on the Dates sheet's grid, the landing on
# today, the pinned month label, the options sheet (Newest first, One per
# event, Missed only) and back to its defaults, its Categories row into the
# picker and closed unchanged, a row tap into its detail sheet and back onto
# the list, the search through the chip row's button, Calendar through the
# view menu. Leaves the overview on Year and This year, as the seed has it.
# - Today is always a Lifting day in this seed, and its first rows are the
#   checkup at today − 40 and the first Lifting session at today − 28: inside
#   This year from mid-February on.
# - The custom span is today alone: the sheet opens on the shown span's
#   start, so Today brings the grid to today's month first, and two taps on
#   today's cell start and end the span — a second day by label could fall in
#   another month.
# - Under Last 90 days nothing but the pinned label names the year (the
#   period's labels and rows name none inside one year), so "{{year}}" finds
#   the pinned label; across New Year (January to March) every label does.
# - The list nav's chevrons (slice 9a): ► lays the ninety days after Last 90
#   days beside it — the seed has nothing in the ninety before, so ► goes
#   first — and lands at its top, where today + 2 is a Lifting day; Today
#   returns to the preset, landing on today; ► then ◄ is the preset again
#   (review 5), so Today is disabled there and not tapped. The totals under
#   the nav read "Gym 4 · Other N · Strength 8": the walk's four days, the
#   standups and the checkup (N varies with the weekday), and Lifting's nine
#   days less the one marked missed; the full prefix and the last part are
#   expected, so a stray "Strength" cannot pass. On 31 December ► is
#   disabled (the year bounds end).
# - The list lands on today, so the checkup at today − 40 is reached with a
#   `scroll-to … --up` before it is expected.
# - The options sheet is modal: the list leaves the semantics tree while it
#   is up, so the per-event row is expected after the sheet closes.
# - The scrubber (slice 5): a native swipe — a real touch, which is what the
#   lane must win from the list — from the lane's middle up past the list's
#   top, which scrubs to the very top: Last 90 days' first row, the checkup
#   at today − 40; a plain scroll of that distance would not get there. The
#   point is in physical pixels (the harness's `x,y`, no logical form): the
#   lane is the rightmost 48 dp, x ≈ 1208 on the Pixel_9_Pro emulator
#   (1280 × 2856 @ 3.0); another screen needs its own x. `drag` cannot
#   scroll a list, so it is not used here.
# - The presence button on a day row (D18 revisited, 2026-10-17): the day
#   panel's button in today's Lifting row marks it missed — the row stays,
#   faded. The day header's count cannot be expected as text: the Standup
#   (workdays, assumed absent) makes it differ by weekday, and a step cannot
#   type the newline between "Today" and its count. So Missed only shows the
#   mark — the row is listed — and a second press marks the day present,
#   which takes the row out of that list. Missed only goes off again; today's
#   Lifting is left marked present, which reads as the seed's unmarked day.
# - The mode chips and the search button yield while the keyboard is up
#   (slice 8a); the harness raises none, so the button that closes the
#   search is in reach after the typing.
