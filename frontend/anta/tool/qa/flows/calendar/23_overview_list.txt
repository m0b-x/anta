# The overview's list (docs/calendar-overview-list-roadmap.md §3.2–§3.6,
# slice 3b): List through the view menu, the Period menu and Custom range…
# on the Dates sheet's grid, the landing on today, the pinned month label,
# the options sheet (Newest first, One per event, Missed only) and back to
# its defaults, a row tap into the calendar and back onto the list, the
# search, Calendar through the view menu. Leaves the overview on Year and
# This year, as the seed has it.
# - Today is always a Lifting day in this seed, and its first rows are the
#   checkup at today − 40 and the first Lifting session at today − 28: inside
#   This year from mid-February on.
# - The custom span is today alone: the sheet opens on the shown span's
#   start, so Today brings the grid to today's month first, and two taps on
#   today's cell start and end the span — a second day by label could fall in
#   another month.
# - Under Last 90 days nothing but the pinned label names the year (the
#   period's labels and rows name none inside one year), so "{{year}}" finds
#   the pinned label; across New Year (January to March) every label does.
# - The list lands on today, so the checkup at today − 40 is reached with a
#   `scroll-to … --up` before it is expected.
# - The options sheet is modal: the list leaves the semantics tree while it
#   is up, so the per-event row is expected after the sheet closes.
# - The scrubber (slice 5): a native swipe — a real touch, which is what the
#   lane must win from the list — from the lane's middle up past the list's
#   top, which scrubs to the very top: Last 90 days' first row, the checkup
#   at today − 40; a plain scroll of that distance would not get there. The
#   point is in physical pixels (the harness's `x,y`, no logical form): the
#   lane is the rightmost 48 dp, x ≈ 1208 on the Pixel_9_Pro emulator
#   (1280 × 2856 @ 3.0); another screen needs its own x. `drag` cannot
#   scroll a list, so it is not used here.
