# Import/export pipeline rules

## Import/Export Pipeline Rules
- Every layer has paired `createX` / `importX` methods on `FolderDao`/`NoteDao`, the matching repositories, and the storage services. `createX` always stamps `createdAt`/`updatedAt` to "now"; `importX` accepts caller-supplied timestamps so a round-tripped archive preserves originals. Never widen `createX` with optional timestamp params — add an `importX` overload instead. A full backup's folders go through `FolderDao.importFolders` in ONE transaction and batch since 2026-11-05 (`325a9ae0`): parents are resolved through the copies made earlier in the same list, each parent's live max position is read once and counted up locally, every row gets its own HLC stamp and outbox entry — the same rows `importFolder` wrote one transaction at a time, which made a 16,384-folder archive take 13 s. A folder whose archived parent is neither a copy made in the same list nor a live folder here restores at the root (the final review's W-7, 2026-11-06, the twin of the notes fallback from `3561409c`): a dangling parent id used to make the folder invisible; the restore appends, so a live local folder keeps its children. One consequence: a restore that throws partway through the folders rolls back every folder (the import reports failure either way). The backup round-trip suites open the real isolate-backed `AppDatabase` and carry a 2-minute `@Timeout` for that reason.
- All UI access to import/export goes through `ImportExportBloc`. Pages dispatch events (`ExportNoteRequested`, `ExportFolderRequested`, `ExportItemsRequested`, `ExportCalendarRequested`, `ExportTextRequested` — a ready text written as a file and shared, the calendar report's Markdown since 2026-10-31: `ImportExportService.exportText({fileName, text, format})` into the temp folder, the same `shareExport` and sweep, `ImportExportOperation.exportText`, its own "Report exported" words through `CalendarExportController.startText`; the browser page's listener ignores the calendar's and the report's operations, whose controllers own their snackbars —, `ImportFileRequested`, `ImportArchiveRequested`) and react to `ImportExportInProgress` / `ImportExportExportSuccess` / `ImportExportImportSuccess` / `ImportExportFailure`.
- Archive format: per-folder `_folder.json` (carries name, `createdAt`, sort orders, and since 2026-11-27 an optional `updatedAt` the import keeps when present), per-note JSON/MD/TXT bodies, top-level `manifest.json` with `version` (`ImportExportService.archiveVersion`). The export writes siblings — folders, a folder's notes, a selection's picked folders and loose notes — in their stored order (position, then id, sorted in the walk, never left to SQLite's plan), and the import recreates directories in the order of their first zip entry (parents before children, never sorted by name), so the manual order round-trips; a directory with no entry of its own (another tool's archive) is rebuilt where its first descendant appears. A Markdown note's import drops only the one blank line (spaces or tabs at most) written after its `# title`. A title or name past its column (`AppConstants.maxNoteTitleLength` / `maxFolderNameLength`) is cut on a whole user-perceived character (`TextFit`, `lib/utils/text_fit.dart` — the one cut for every title that must fit a column, the sync conflict copy's and the editor's kept-as-new numbering too; when not one whole character fits, it keeps the code units that do, a surrogate pair whole, and a folder whose cut is still empty takes its directory's name), and a note keeps the whole title in its body — the file's full text for a Markdown file that opens with its `# ` title, a `# ` heading on top for JSON and for a title taken from the file name (a `.txt`, or a `.md` without a heading); a numbered copy of a taken name (` (n)`) is cut the same way. Each entry path is normalised before grouping (2026-11-27): `.` and `..` are resolved and any `..` left at the front dropped, so no folder is named `.` or `..` and nothing lands outside the import's target. A note file that is not UTF-8, is malformed JSON, or whose JSON `title` / `content` is not a string is skipped and counted (`ConvertImportResult.notesSkipped`), and the browser's import snackbar adds `importSkippedFiles` when any was; a `_folder.json` that cannot be read is not skipped — its folder imports under the directory's name with default metadata. When bumping the manifest schema, also bump `archiveVersion` and accept the previous version in `_assertSupportedManifest`. Reject newer versions with `UnsupportedArchiveVersionException` before any DB writes.
- Temp files (S18, 2026-11-07): every temporary export — note files, `.zip` archives, the `.ics` (`anta_events_…`) and the report (`anta_report_…`) — lands in a folder of its own, `<temp>/anta_exports/anta_export_<unique>/<file name>` (2026-11-27: the name the recipient sees stays the title, and a later export of the same name never overwrites one a desktop sheet still reads; older builds wrote them loose in `anta_exports/` or at the temp root), the database share's snapshot alone in `<temp>/anta_db_share_<ms>/<name>.db`. `shareExport` deletes a temporary export after the share sheet returns — on Windows, macOS and Linux only when the share threw, since a desktop sheet may still read the path (a mail client attaching it), so there the sweep takes it (2026-11-27); a snapshot (`ExportResult.snapshot`) goes with its folder only when the share threw or Android answered other than `unavailable` (share_plus copies the file first) — on desktop and on `unavailable` it waits for the next share (`snapshotForShare` deletes earlier folders) or the sweep; `cleanupExport` deletes the file with its own folder, and only a prefixed folder directly in the temp directory (a snapshot's) or in `anta_exports/` (an export's). `ExportResult.file(path)` (`isTemporary = false`) still keeps a file the app owns but has no production caller. `sweepStaleExports` runs at app startup from `main.dart` and deletes, after 24h, only `anta_`-prefixed entries: `anta_export_*` folders and loose files in `anta_exports/`, `anta_db_share_*` folders, prefixed top-level files with a known extension — never another app's files in the shared Windows `%TEMP%`. New export entry points must funnel through these helpers — do not invoke `SharePlus` directly from blocs/pages.
- Calendar `.ics` export: `IcsSerializer` (floating local time, `DTSTART` moved to the first real occurrence, workdays = `BYDAY` + holiday `EXDATE`s, holidays-only/specific dates = `RDATE`s, 730-day expansion bound) → `ImportExportService.exportCalendar` → `ExportCalendarRequested` on `ImportExportBloc`. `ExportFormat` deliberately does **not** grow an `ics` variant — it would leak into every note-format picker; `.ics` rides `ExportResult.eventsExported` and the sweep list instead.
