## Import/Export Pipeline Rules
- Every layer has paired `createX` / `importX` methods on `FolderDao`/`NoteDao`, the matching repositories, and the storage services. `createX` always stamps `createdAt`/`updatedAt` to "now"; `importX` accepts caller-supplied timestamps so a round-tripped archive preserves originals. Never widen `createX` with optional timestamp params — add an `importX` overload instead. A full backup's folders go through `FolderDao.importFolders` in ONE transaction and batch since 2026-11-05 (`325a9ae0`): parents are resolved through the copies made earlier in the same list, each parent's live max position is read once and counted up locally, every row gets its own HLC stamp and outbox entry — the same rows `importFolder` wrote one transaction at a time, which made a 16,384-folder archive take 13 s. A folder whose archived parent is neither a copy made in the same list nor a live folder here restores at the root (the final review's W-7, 2026-11-06, the twin of the notes fallback from `3561409c`): a dangling parent id used to make the folder invisible; the restore appends, so a live local folder keeps its children. One consequence: a restore that throws partway through the folders rolls back every folder (the import reports failure either way). The backup round-trip suites open the real isolate-backed `AppDatabase` and carry a 2-minute `@Timeout` for that reason.
- All UI access to import/export goes through `ImportExportBloc`. Pages dispatch events (`ExportNoteRequested`, `ExportFolderRequested`, `ExportItemsRequested`, `ExportCalendarRequested`, `ExportTextRequested` — a ready text written as a file and shared, the calendar report's Markdown since 2026-10-31: `ImportExportService.exportText({fileName, text, format})` into the temp folder, the same `shareExport` and sweep, `ImportExportOperation.exportText`, its own "Report exported" words through `CalendarExportController.startText`; the browser page's listener ignores the calendar's and the report's operations, whose controllers own their snackbars —, `ImportFileRequested`, `ImportArchiveRequested`) and react to `ImportExportInProgress` / `ImportExportExportSuccess` / `ImportExportImportSuccess` / `ImportExportFailure`.
- Archive format: per-folder `_folder.json` (carries name, `createdAt`, sort orders), per-note JSON/MD/TXT bodies, top-level `manifest.json` with `version` (`ImportExportService.archiveVersion`). When bumping the manifest schema, also bump `archiveVersion` and accept the previous version in `_assertSupportedManifest`. Reject newer versions with `UnsupportedArchiveVersionException` before any DB writes.
- Temp files (S18, 2026-11-07): note files and `.zip` archives land in `<temp>/anta_exports/` (their names are the user's titles), the `.ics` and report exports at the temp root as `anta_events_…` / `anta_report_…`, the database share's snapshot alone in `<temp>/anta_db_share_<ms>/<name>.db`. `shareExport` deletes a temporary export after the share sheet returns; a snapshot (`ExportResult.snapshot`) goes with its folder only when the share threw or Android answered other than `unavailable` (share_plus copies the file first) — on desktop and on `unavailable` it waits for the next share (`snapshotForShare` deletes earlier folders) or the sweep; `cleanupExport` deletes only a prefixed folder directly in the temp directory. `ExportResult.file(path)` (`isTemporary = false`) still keeps a file the app owns but has no production caller. `sweepStaleExports` runs at app startup from `main.dart` and deletes, after 24h, only `anta_`-prefixed entries: files in `anta_exports/`, `anta_db_share_*` folders, prefixed top-level files with a known extension — never another app's files in the shared Windows `%TEMP%`. New export entry points must funnel through these helpers — do not invoke `SharePlus` directly from blocs/pages.
- Calendar `.ics` export: `IcsSerializer` (floating local time, `DTSTART` moved to the first real occurrence, workdays = `BYDAY` + holiday `EXDATE`s, holidays-only/specific dates = `RDATE`s, 730-day expansion bound) → `ImportExportService.exportCalendar` → `ExportCalendarRequested` on `ImportExportBloc`. `ExportFormat` deliberately does **not** grow an `ics` variant — it would leak into every note-format picker; `.ics` rides `ExportResult.eventsExported` and the sweep list instead.
