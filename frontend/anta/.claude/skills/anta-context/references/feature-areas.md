# Main feature areas

Reference, not rules — moved verbatim from `COPILOT_CONTEXT.md` on 2026-10-11 (sections: Main Feature Areas, its generic bullets — the calendar ones are in `calendar-events/references/context-log.md`). Read only the part the task needs.

- `lib/pages/optimized_folder_content_page.dart`: main folder/note browser with nested folders, pagination, sorting, reordering, drag-and-drop moves, a bottom create bar, and navigation. **Reorder and move (S17, 2026-11-08):** positions are gapped (`drift-migrations/references/persistence-rules.md`); `planGappedPositions` (`lib/utils/position_plan.dart`) works in keys (the position, negated under `positionDesc`), keeps the longest strictly increasing run in place — so one drag moves one row — and spaces every other run evenly between its new neighbours; with no room the window widens one neighbour at a time toward the nearer end until its average gap reaches `_widenedGap(m)` (`1 << (2 × m.bitLength)`, capped at `positionStride ~/ 2`), an open end steps by the stride, a closed group is never rewritten whole, and a stored position past ±2^61 respreads the group from 0. `applyOrder(parentId, loadedOrder, descending, windowAtTop)` reads the group in display order and `spliceLoadedOrder` places the loaded page in it — unloaded rows above the window stay above; `windowAtTop` for the first drag after a title, date or label sort, whose page was never a stretch of the position order — then batch-updates the changed rows and the repositories announce only those ids; `MixedReorderService.reorderMixed` serialises per parent and the page sends only the kinds a drag changed. `NoteDao.moveNotes` / `FolderDao.moveFolders` move a selection in one transaction under one HLC (`IN` lists chunked at 500; the folder cycle check walks the target's ancestors); duplicate names follow the single-item rule through `planBulkMove` (`bulkMoveNameKey` = `trim().toLowerCase()`, empty exempt) into a `BulkMoveResult` (`moved`, `duplicates`, `unchanged`). `MoveHistoryService` keeps undo units (`batchId ?? id`; `moveHistoryMaxUnits` 20, `moveHistoryMaxEntries` 2000, the newest unit always whole); `undoBatch` restores a unit, falls back to `_firstAvailableFolderId` for a vanished source, and says `moveUndone` only when every item went back. The page keeps its optimistic order only while `_reorderPending` is set (cleared by the confirming load, a different id set, leaving selection or a failed write); drops queue on `_dragChain`, each working out its flip, rollback point and `windowAtTop` at its turn, written even after the page was popped and dropped only when `_dragEpoch` moved (an earlier write failed); a failed write restores and saves the flipped sorts before any `mounted` check, then reloads.
- `lib/pages/optimized_note_editor_page.dart`: main note editor with `re_editor`, markdown toolbar, preview/split modes, auto-save, note position persistence, search/replace, sharing, and debug overlays. Since 2026-09-04 (review Session 6) the page `State` is 26 fields over six **page-owned controllers** in `lib/controllers/` — plain classes / `ChangeNotifier`s, never a BLoC on the typing path: `EditorSettingsController` (the whole editor settings bundle read in one statement via `SettingsService.getEditorSettings`, font-size taps with debounced writes; the editor mounts only once it has loaded so the `CodeEditor`'s `ValueKey` is final on first build), `NoteEditorPositionController` (the saved-position restore as an explicit join of "position loaded" and "editor ready", stored in **absolute** line numbers through `index2lineIndex`/`lineIndex2Index` so heading folding can land later; since 2026-09-07 its `loaded` flag is the third half of the mount gate — `_isLoading` waits on content, settings bundle AND the position read — and the restore sets the caret synchronously and hands the scroll to the fork's `CodeScrollController.makeCenterIfInvisibleOnLayout`, which the editor's first layout consumes, so the first frame the editor paints is already scrolled to the stored line — the old post-frame + 100 ms timer `makeCenterIfInvisible` painted the top of the note first and then jumped, a "fast scroll down" on slow devices; `test/widgets/optimized_note_editor_page_test.dart` pins the first frame. The same day the gate grew to every input of the first frame — `_renderConfigLoaded` (money config + colour palette, opened in the initial `_reloadSettings`'s `finally`, the two reads in parallel) and `_barSettled` (the bar bloc's Loaded *or* Error answer) — because each used to land after the mount and restyle money rows / coloured runs or reflow the toolbar; the loading body is blank and the finished body fades in once, see "Toolbar helper" below), `NoteSaveCoordinator` (auto-save, early create, duplicate-title rules, `hasChanges`), `EditorEditTracker` (paste reflow through `PasteLineBreaker`, Enter list continuation — nested items included — and the `runGuarded` re-entrancy guard every programmatic insert uses; since the 2026-09-05 Session 3 review an Enter is recognised by its exact growth, one line break plus the indentation `applyNewLine` copied, never by caret position alone — a Tab indent, a typed space at the indent column and a short paste ending in a newline used to grow a list marker — and growth notified while the fork's `isRestoringHistory` is up is undo/redo restoring text, never a paste to reflow or an Enter to continue), `NoteEditorStatsTracker`, `EditorRenderController`. The page never reaches a DAO. Session 6 review (2026-09-05): `NoteSaveCoordinator.contentLoaded()` re-baselines auto-save on the loaded text — the coordinator starts in `initState` against an empty baseline, so `loadText` used to mark every opened note dirty and rewrite it five seconds later, bumping `updatedAt`/`version`/`hlcTimestamp`; `noteCreated` baselines on the title and content the create actually dispatched and arms the debounce when the editor has moved on (text typed while the create was in flight was stamped as saved); the lifecycle path never overwrites a pending create; the bloc listener ignores loads and creates for other notes (`OptimizedNoteBloc` is one app-wide instance and `MaterialPageRoute` keeps a buried editor's listener alive); the pop proceeds even when the exit flush throws; `didPushNext` force-saves before a route covers the editor; `markChanged` arms the save, not just the dot. The tracker and both paste policies are fence-aware through `EditorRenderController.lineInFence`/`lineInFenceBody`, and both event sheets construct their own `EditorEditTracker`, so Enter continues lists there too.
- `lib/widgets/note_search_bar.dart` + `lib/widgets/note_match_list_sheet.dart`: in-note find/replace. The bar is a single row: search pill carrying the `_MatchCountChip` inside its trailing edge, then prev / next / options / close as plain icon buttons. The arrows stay mounted and disabled with no query, so the first keystroke never reflows the cluster; the trailing button clears a non-empty query and closes search once empty (Android search-view semantics — there is only one ✕). The counter renders **numbers only** — `noSearchResults` and `searching` survive as its tooltip and semantics label but are never laid out, because "Keine Ergebnisse gefunden" is wider than the counter's whole footprint and laying it out is what starved the query field. Below `compactWidthThreshold` the controls narrow (never shorten). The counter is the jump affordance: tapping `3/50` opens `NoteMatchListSheet`, which lists every match as line number + trimmed source snippet with the hit bolded, pre-scrolls to the current match, and pops the picked index; long-pressing it opens the same sheet with the header's jump-to-number field focused. That field previews as you type (list scrolls, row outlines) and only moves the note on submit, clamping out-of-range input — typing "15" passes through "1", and jumping live would fling the editor twice for one intent. Rows come from `ReEditorSearchController.previewAt(index)`, built on demand so thousands of hits materialize no snippet the list does not draw. Jumps go through `goToMatch`, which delegates to the fork's `CodeFindController.goToMatch` — never step `nextMatch()` in a loop to reach an index. Keep the counter's index padded to the total's width with tabular figures (otherwise the row shifts while stepping), and keep the sheet padded by `viewInsets.bottom`: the search field holds focus while the sheet is up, so the keyboard stays on screen.
- `lib/widgets/markdown_toolbar.dart`: configurable shortcut and utility toolbar. Use `UtilityButtonDefinition` as the registry for utility buttons.
- `lib/pages/markdown_settings_page.dart`, `shortcut_editor_page.dart`, `note_bar_assignment_page.dart`: markdown shortcut profiles and per-note toolbar assignment. The settings page body is a `CustomScrollView`: the config sections are `SliverToBoxAdapter`s (each keeping its own height-fold animation) and the shortcut list is a `SliverReorderableList` so `EdgeDraggingAutoScroller` can scroll the page while a card is dragged — never nest it back into a shrink-wrapped list, that is exactly what broke drag auto-scroll. A pinned `SliverPersistentHeader` carries the search field and category filter chips; while a search query or chip is active the list falls back to a plain `SliverList` and drag is disabled, so a shortcut can never be moved to a position the user cannot see. Section fold state is persisted (`SettingsKeys.markdownSectionsCollapsed`, a comma-separated set of *collapsed* ids so the empty default keeps everything open) and restored without animating on entry; an app-bar icon folds/unfolds all sections at once. Fold sections through `_FoldableContent`, never a `TweenAnimationBuilder` around a prebuilt child — `Align`'s `heightFactor` only clips painting, so the old shape still built and laid out every collapsed section on each rebuild (the collapsed toolbar section was constructing a live `MarkdownBar` on every keystroke in the shortcut search). A settings list only grows a search field once it exceeds `AppConstants.listSearchThreshold`; the utility-button list is below that today, so its search path is inert until the `UtilityButtonDefinition` registry grows. The "Text colors" row folds exactly like its neighbours (a `ListTile` there previously supplied its own colors/height and stood out); the actual navigation to `MarkdownColorsPage` lives on an "Edit colors" button inside the fold, not on the header itself.
- `lib/pages/counter_management_page.dart` and `counter_per_note_page.dart`: global/per-note counter workflows for repeated numeric metrics.
- `lib/services/counter_service.dart`: counter cache, debounced writes, pinning, ordering, import/export, and flush behavior.
- A counter value is a PN-counter (**v49**, S20, D8 A; `lib/database/crdt/pn_counter.dart`): `epoch_hlc` + `epoch_value` (the last absolute write) and `shards` (`{replicaId: [p, n]}`); `value` stays the materialised `epochValue + Σ(p − n)` every reader reads. The flush writes taps as taps (`CounterDao.applyCount`, on this database's `replica_id`); a reset, a typed value, a restore and a counter's first value start an epoch at their own stamp; a value first written by a tap starts at the genesis epoch `''`; a tap on a tombstoned value starts an epoch at the tombstone's stamp. `replica_id` lives in `sync_metadata` beside `replica_id_device` (the install `device_id` it was minted under), minted at every bind and unbind, on the first tap when absent or when `replica_id_device` is not this install's (Android backup copies the file, not the `device_id`), and dropped from an imported `.db` by the import's verifier — never the install `device_id` itself.
- A per-note value dies with its note: every local note delete (single, selection, folder) tombstones the note's live values in its own transaction under its stamp (`CounterDao.tombstoneValuesOfDeletedNotes`, one set-based statement, `idx_counter_values_note`); a write for a tombstoned note writes nothing; the export skips values of tombstoned notes; merged note deletes are swept by the puller (`sync-and-accounts.md`).
- `lib/services/auto_save_service.dart`: note content save reliability. Be careful with debounce, interval saves, lifecycle flushes, and retry behavior. `forceSave` resolves title and content only after any in-flight save has finished (2026-09-05 — text typed during that wait was stamped as saved); `onContentChanged`/`startTracking` are inert after `dispose`; the retry ladder is three attempts at 2/4/8 s and the 30 s interval keeps retrying after that. A soft-deleted note is never updated: `NoteDao.updateNote` and `NoteStorageService.updateNote` both stop at a tombstone, so a late flush cannot stamp it or resurrect its chunks. **Save status (2026-10-01):** `startTracking` ends on `saved` unless a write is in flight — a fresh baseline has nothing unsaved, and it is what answers the `unsaved` a load leaves behind (`loadText` notifies like an edit) now that the editor's mount no longer re-arms a debounce to clear it. The app bar never listens to the service's notifier directly: `NoteSaveCoordinator.saveStatus` is the coordinator's own notifier, fed by `_relaySaveStatus` under the rule `_setHasChanges` follows — written at once outside a frame, after the frame when the change is detected inside one — because the same controller notification that flags the page dirty also flips the status, and a builder above the editor is already clean when one lands mid-build.
- `lib/services/backup_service.dart`: JSON backup restore (onboarding, `qa_bootstrap`); the uncalled exporter went in S18 (2026-11-07) and its version-8 output is rebuilt by `test/services/support/backup_archive.dart` for the round-trip suites; the onboarding restore decodes once in an isolate (`readBackupFile` → `validateBackupData` / `importFromData`). Keep versioned compatibility when adding persisted fields.
- `lib/services/import_export_service.dart`: per-note and per-folder share/import (single files or `.zip` archives). Owns archive `manifest.json` versioning, temp-file cleanup, and unique-name resolution. The matching `ImportExportBloc` (`lib/bloc/import_export/`) is the only allowed entry point for the UI's archive flows — the one exception is the Databases page's `.db` share, which calls `shareExport(ExportResult.snapshot(path))` on the service with `DatabaseManager.snapshotForShare(name)`'s copy (S18, D11, 2026-11-07). Since S18 the zip is written entry by entry (`ZipFileEncoder`, deflate level 1, a `.part` name renamed when whole, a failed write closes the handle and deletes it) and read entry by entry (`InputFileStream`, `ArchiveFile.clear()` after each entry); sibling folders get unique directory names like notes do.
- Settings pages (the settings rework, `docs/settings-rework-roadmap.md`, 2026-10-31 → 11-01): the drawer lists places, and every settings page is chosen on the hub `lib/pages/settings_hub_page.dart` (one row per page with a subtitle, a search over titles, subtitles and the pages' section titles); back always lands on the route beneath (no drawer reopening); every page speaks the settings kit (`lib/widgets/settings_section_list.dart`) under `SettingsAppBar(identifier:)`; `AlertSettingsPage` and `FastingSettingsPage` hold what used to be Calendar settings' alerts and fasting sections, Calendar settings keeps Holidays · More settings (the rows to Appearance, Categories, Fasting, Alert settings) · Filtering · Events with no page-level reset, General (`settings_page.dart`) is titled like its hub row; the Databases, Sharing, Permissions, Developer options, Markdown and per-note pages carry ids on every row and keep their own idioms until the §9 items of the record move them.
- `lib/services/database_manager.dart`: multi-database management and active database selection; `checkpoint(name)` folds the `-wal` back before a rename (hard — a blocked checkpoint fails the rename before any file moves) and a delete (best-effort) — since 2026-11-01, because the `.db` is renamed before its sidecar and a kill between the two would strand an inactive database's last writes (the live connection through `AppDatabase.openInstanceOf`, which never opens anything; a short-lived read-write connection for an inactive file that has a `-wal`; it throws `StateError` when a reader holds the WAL). A share no longer checkpoints (S18, D11, 2026-11-07): `snapshotForShare(name)` deletes earlier `anta_db_share_*` folders, then runs `VACUUM INTO` on a short-lived read-write, never-create connection in `Isolate.run` — open database or not, so the app's Drift connection keeps writing — into `<temp>/anta_db_share_<ms>/<name>.db`; a failure deletes its folder and the page shows `shareError`. Storage hygiene (S16, D13, v47, 2026-11-08): a tombstoned note's chunk rows are hard-deleted on all four tombstone paths (the note row keeps its tombstone and stamp), v47 purged the ones older builds kept; Optimize is `AppDatabase.optimize` — FTS rebuild, tombstones' `'delete'` rows, then `VACUUM` (needs RAM about the database's size under `temp_store = MEMORY`) — with a "Reclaimable" caption from `freelist_count × page_size`; launch opens the database before Firebase and shows `AppBootstrap` only while a migration runs or when the open fails. `importDatabase` (S19, 2026-11-08) copies the source and its `-wal` and hot `-journal` in 1 MiB chunks to `<name>.db.import-<ms>` beside the target under `DatabaseImportDialog` (glue over `AppDialogs.progress`: determinate bar + Cancel, then "Checking the file..." with Cancel disabled; the Databases page and the onboarding restore share it), then renames only what `verifyImport` accepts, after deleting any orphan sidecar beside the target — the real check (`verifyImportFile`, `Isolate.run`, read-write never create, the `-wal` folded and a hot journal rolled back first): header (magic, page size, versions 1 or 2), `page_count × page_size == length`, `user_version ≤ DatabaseSchema.currentVersion`, `quick_check`, ANTA's shape (`user_version ≥ 1`; `notes` / `folders` / `content_chunks` with their first-schema columns, plus `is_deleted` / `hlc_timestamp` — and `content_hash` on `content_chunks` — at the current version) — refusing with `DatabaseImportCorrupt` / `DatabaseImportTooNew` / `DatabaseImportNotAnta`, each its own message; any failure or cancel deletes the temp, and `sweepStaleImports()` deletes leftovers before `runApp`; widget tests replace `verifyImport` with a fake.
