## UI And UX Direction
- This is a productivity/tracking app, not a marketing site. Favor compact, stable, repeat-use interfaces.
- Use Material 3 and existing constants for spacing, text, colors, icons, and dimensions.
- **The palette is the Material 3 baseline scheme, declared token by token in `lib/constants/app_theme.dart` (`AppTheme.lightScheme` / `darkScheme`, wired into `main.dart` as `AppTheme.light()` / `dark()`) — never `ColorScheme.fromSeed`.** Tonal spot desaturates whatever it is handed: `deepPurple` lands on `#68548E` and even seeding with the approved mock's own `#6750A4` lands on `#65558F`, so a seed cannot reproduce the palette the mock was approved in. `SurfaceRoles` (an extension on `ColorScheme` in `lib/constants/app_colors.dart`) names the layering, and the rule is: **the page ground is one tone under the row groups in both themes** — light puts `surface` groups on a `surfaceContainer` ground, dark puts `surfaceContainer` groups on a `surface` ground (`pageGround`, `rowGroup`), the hairline between rows is opaque `surfaceContainerHighest` (`rowDivider`), and menus are `surfaceContainerHigh` at radius 12 (`menuSurface`, plus `popupMenuTheme` in `AppTheme`). Browser pages (`OptimizedFolderContentPage`, `AllNotesPage`, `SearchPage`) set `Scaffold.backgroundColor` to `pageGround` and their bars sit on the same ground with `surfaceTintColor: Colors.transparent` and `scrolledUnderElevation: 0`, so nothing changes tone on scroll; `scaffoldBackgroundColor` stays at the theme default (`surface`) because the editor body and the settings pages want it. Folder icons are `primary` (`AppColors.folderIcon`) — the mock carries exactly one accent. Guards: `test/constants/app_theme_test.dart` and the "the mock palette" group in `test/widgets/optimized_folder_content_page_test.dart`.
- Keep controls touch-friendly: icon buttons, tooltips, menus, toggles, sliders, reorder handles, and clear destructive confirmations.
- Avoid layout shifts in editor, toolbar, counters, and folder/note lists. Stable dimensions matter more than decorative styling.
- **A keyboard inset that no keyboard accounts for never reaches a route (2026-10-01).** Android's embedding defers the IME inset while the keyboard animates and, when the animation ends, replays the insets it saved as the animation began (`ImeSyncDeferringInsetsCallback`); an inset change that lands in between is swallowed, so `viewInsets.bottom` can be left at the keyboard's height with the keyboard gone, and nothing corrects it until the window's insets next change. Every surface that pads by the inset then floats above an empty strip until the app is restarted — the folder browser's create bar in the middle of the screen was the report, and the same value collapses the calendar grid to a week, shortens every `Scaffold` body and is the "blank, dead sheet" the clearance tests describe. Two pieces close it, both wired in `main.dart`'s `MaterialApp.builder`, **above the navigator** so no page needs a guard of its own: `KeyboardInsetGuard` (`lib/widgets/`) republishes `MediaQuery.viewInsets` and the `padding` derived from it through the pure `KeyboardInsetTrust` (`lib/utils/`), whose whole rule is that **with nothing focused the inset may fall, never rise, and never rest above zero** — every input closes its connection on losing focus, so an unfocused app's keyboard can only be leaving. A real dismissal's falling frames pass straight through; an inset at rest for `settleWindow` (400 ms), or any inset while the app is not resumed, is dropped. While **any** non-scope focus node holds the focus the raw value is believed as it is, deliberately: the guard cannot tell a text field from a focused button, and a wrong refusal hides the field behind its own keyboard. That case is what the second piece is for — each time a non-zero inset comes to rest the guard calls `WindowInsetsResync.request()` (`lib/services/`, channel `com.alexzamfir.anta/window`), and `MainActivity.resyncInsets` calls `window.decorView.requestApplyInsets()` (API 30+ only — nothing defers insets below it), so the window dispatches its current insets again, the engine's listener passes them through and the view republishes its metrics: the platform value itself is right again within the window (repeated up to `repeatLimit` times while an inset is being held back, since a cure can be lost to a second stale delivery in the same frame). **It must stay a dispatch through the hierarchy** — handing the view its `rootWindowInsets` with `onApplyWindowInsets` was the first attempt and is wrong in three ways an independent review found the same day: outside a dispatch `View.onApplyWindowInsets` falls back to `fitSystemWindows`, which dispatches a compatibility `WindowInsets` with no IME type (two metric packets per call, measured; an animation starting between them can save the compatibility object as the insets to replay — a new stale state), root insets still carry the display cutout the hierarchy strips, and below edge-to-edge they still carry the navigation bar. What it cannot reach is a callback whose animation never ended and which therefore keeps consuming dispatches; the next keyboard animation releases that one, and the guard masks it meanwhile. Rules that follow: **read the keyboard inset through `MediaQuery` only**, never from `View.of(context)` or the platform dispatcher, which bypass the guard; the guard's `MediaQuery` is in the tree even when it corrects nothing (swapping it in would remount the navigator); and `main.dart`'s unfocus on `paused` is load-bearing for it — that is what leaves nothing focused on resume. Suites: `test/utils/keyboard_inset_trust_test.dart`, `test/widgets/keyboard_inset_guard_test.dart`, `test/services/window_insets_resync_test.dart`, `test/android/window_channel_test.dart` (the channel is spelled in Dart and in Kotlin), `test/widgets/keyboard_inset_wiring_test.dart` (the three lines of `main.dart` no widget test can reach — the mount, the resync hook, the unfocus on `paused` — pinned as text), and the browser's own regression in `optimized_folder_content_page_test.dart`. Proved on the emulator by delivering window metrics through the VM service the way the engine does (`PlatformDispatcher._updateWindowMetrics`, from a timer — never inline, an evaluation can land mid-build): the routes read 0 for as long as a 900 px inset was held, and the platform value was back at 0 about a settle window after the last delivery. **Not proved:** the emulator's keyboard never docks, so neither the phone's own trigger nor a resync with a docked keyboard at rest has been observed on a device.
- Keyboard avoidance in the note editor is manual and gated, not `Scaffold`'s: the editor Scaffold sets `resizeToAvoidBottomInset: false` and pads its body by `_keyboardInset(context)`, which only trusts `viewInsets.bottom` while the page owns an input connection (`_contentHasFocus`, mirrored from `_contentFocusNode`, or an open search bar). Android can hand back a stale keyboard inset after a resume — ungated, that inset floats the markdown toolbar above an empty strip until the app is restarted. The page's gate predates the app-wide `KeyboardInsetGuard` above and stays for what the guard does not do: it also ignores a real keyboard that belongs to a dialog over the editor. The same gated value drives `previewWhenKeyboardHidden` and the toolbar's bottom safe-area spacer (`viewPadding.bottom` when no keyboard). `main.dart` completes the pair by unfocusing on `AppLifecycleState.paused` so the IME animation finishes while the window is still live.
- Times are typed on `TimePadSheet` (in-app keypad; `showTimePicker` is gone): the pure `TimePadEntry` owns the rules — auto-advance, disabled impossible keys, auto-finish on the last minute digit or `:00`/`:30`, AM/PM as the finishing key on a 12-hour clock — and the written-to row flashes (`ValueChangeHighlight`). Time labels honour the device's 24-hour setting via `EventTimeFormatter`.
- For any capture-oriented feature, prefer quick capture patterns: reusable templates, pinned counters, recent/frequent actions, clear save status, and minimal taps.
- Respect light/dark/system themes and supported locales.
