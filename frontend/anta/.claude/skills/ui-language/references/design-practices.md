## 1. The rule stack

ANTA's own rules come first (48 px targets, stable layouts, the UI language's idioms and metrics, `ui-mock`'s principles), then WCAG 2.2 (W3C Recommendation; approved as ISO/IEC 40500:2025 on 2025-10-21; WCAG 3.0 is a 2026-09-10 Working Draft whose contrast algorithm "is yet to be determined"), then Android and Material, then Apple and Windows for the desktop builds. A finding names the rule it is judged against: spec, app rule, WCAG SC, Android, Flutter default.

Where the sources disagree, settled 2026-10-21:

- **Target size.** WCAG 2.5.8 (AA) 24×24 CSS px, 2.5.5 (AAA) 44×44; Android 48×48 dp; Apple 44×44 pt on iOS and 28×28 pt on macOS; Flutter desktop defaults to `shrinkWrap` targets and compact density (32 px buttons). On touch surfaces the app rule (48) wins; a desktop build may shrink-wrap but never below 24.
- **Large text for contrast.** WCAG: 18 pt (≈24 px) or 14 pt bold (≈18.5 px); Android: 18 sp or 14 sp bold; `textContrastGuideline`: 18, or 14 with `FontWeight.bold`, on the unscaled size. Judge against WCAG, the strict one; a green `meetsGuideline(textContrastGuideline)` is a floor, not compliance.
- **Colour tables.** `ColorScheme.fromSeed` in 3.44.2 produces the 2021 spec (material_color_utilities 0.13.0 has no `SpecVersion`); the 2025/2026 specs (dark surface tone 4, containers at 6/9/12/15, `onSurfaceVariant` 4.5:1 light / 6:1 dark, `outlineVariant` 1.5:1) describe Android, not ANTA, whose `AppTheme` and `SurfaceRoles` are explicit. Compute contrast from the app's actual tokens; use role semantics for intent only.
- **Material 3 Expressive** is Android practice, not Flutter 3.44 practice (§5): specs use the SDK's `Durations` / `Easing` and the 2021 type scale; Expressive stays reference until the owner upgrades the toolchain.
- **High contrast.** `MediaQueryData.highContrast` is updated only on iOS in 3.44; the Android `AccessibilityBridge` marks it NOT SUPPORTED, and Android 16's "outline text" does not reach Flutter text. Never spec a variant that depends on it.
- **Text-scale clamps.** Flutter clamps `NavigationBar` labels at 1.3, `AppBar` titles at 1.34 and `MaterialBanner` at 1.5; ANTA clamps per surface. WCAG 1.4.4 and Apple want content text at 200 % without truncation — a clamp is acceptable only on chrome that has an alternative (tooltip, long-press). "1.3" in a review matrix is a heuristic step, not an Android one.
- **Vision versus measurement.** A ±1 dp spec cannot be verified by eye from a render Claude Code resizes to fit 2000 px; geometry and colour come from `tester.getRect` / `getSize`, `RenderParagraph` / `TextPainter` metrics and token values. Vision is for hierarchy, balance and the squint test.
- **Self-verification.** Opus 5-family agents get no generic "verify your work" lines; the independent check is the `design-reviewer`, in a fresh context, never the designer re-grading its own direction.
- **Questions.** A background agent cannot ask; the designer picks a default for every open question and lists it as a lettered, reversible decision for the lead to put to the owner.

## 2. Targets, spacing, density, states

- Android: ≥48×48 dp (≈9 mm; 7–10 mm recommended), 8 dp apart, allowed to extend past the visual bounds; Material components enforce it through `MaterialTapTargetSize.padded`, custom widgets must (`TapTargetPadding` in `form_rows.dart`) — support.google.com/accessibility/android/answer/7101858; developer.android.com accessibility/apps (2026-09-22).
- Apple HIG: iOS/iPadOS controls 44×44 pt by default with a 28×28 pt minimum; macOS 28×28 default, 20×20 minimum; ≈12 pt of padding around bezeled controls — developer.apple.com HIG accessibility (2025-03-07 revision).
- WCAG 2.2 SC 2.5.8 Target Size (Minimum, AA): 24×24 CSS px, with the spacing, equivalent, inline, user-agent and essential exceptions; 2.5.5 (AAA) 44×44; WCAG2ICT (2025-12-11, informative) maps px to dp, pt and epx.
- Desktop: `ThemeData()` defaults to `shrinkWrap` tap targets and `VisualDensity.compact` on desktop, `padded` and standard on mobile; one density unit ≈4 px over −4…+4 and changes neither text, icon nor padding sizes — api.flutter.dev `MaterialTapTargetSize`, `VisualDensity` (3.44.2).
- Grid: 8 dp rhythm, 4 dp for icons, type and small elements ("stick to measurements of 4 and 8") — developer.android.com grids-and-units (2026-10-05).
- Thumb reach (Hoober, uxmatters 2017-03-06): centre targets ≈7 mm and corner targets ≈12 mm for a 95 % hit rate; 75 % of users touch with one thumb; primary content centred, secondary actions along the top and bottom edges.
- State layers (M3 StateTokens): hover 8 %, focus 10 %, pressed 10 %, dragged 16 %; disabled content 38 %, disabled containers and outlines 12 %. That the layer takes the content's colour is M3 practice not verified on a primary page.
- Edge-to-edge (API 35+, no opt-out once targeting API 36): backgrounds and dividers run under the system bars, text and buttons are inset; no tap or drag targets inside the gesture insets; gesture navigation stays transparent, a scrim only for 3-button navigation — developer.android.com edge-to-edge. Play requires targeting API 36 from 2026-08-31 (extension to 2026-11-01); Flutter 3.44.2's Gradle plugin defaults compile and target SDK to 36.

## 3. Contrast and colour roles

- WCAG 1.4.3 (AA): 4.5:1 for text, placeholders included; 3:1 for large text; ratios are never rounded (4.499:1 fails); inactive controls and pure decoration are exempt — w3.org Understanding contrast-minimum.
- WCAG 1.4.11 (AA): 3:1 for the visual information that identifies a component and its states (focus, selected); no boundary is needed when text or an icon identifies the control; hover indicators are supplemental — Understanding non-text-contrast (2026-09-06).
- WCAG 1.4.1 (A): colour is never the only carrier of information, state or action — Understanding use-of-color (2025-09-16).
- Roles in the 2021 spec, what Flutter 3.44 builds: `onSurface` at tone 10/90 (≈9:1 in light) for primary text; `onSurfaceVariant` designed for 4.5:1 — secondary text and metadata; `outline` for 3:1 edges; `outlineVariant` decorative (≈1.5:1) — dividers and chip borders at rest, never a state indicator; `primary` for the one interactive accent. M3 components use tonal surface containers instead of elevation overlays since MDC 1.11 (Flutter: the `surfaceContainer*` tiers; `background`, `onBackground`, `surfaceVariant` deprecated since 3.18) — material-color-utilities ColorSpec, docs.flutter.dev new-color-scheme-roles (2026-05).
- Dark theme: check contrast in both themes (Apple). The 2025 spec darkens phone surfaces (tone 4, containers 6/9/12/15), so a tier change alone barely delimits a control in dark — give a control an outline or a state layer, not a tier.
- Measuring: compute WCAG relative-luminance ratios from the app's `ColorScheme` and `SurfaceRoles` per theme, alpha composited over the real ground and with the state layer included (`Color.computeLuminance`); `textContrastGuideline` estimates naively from pixels, reads only `Text` / `EditableText`, skips links.

## 4. Type and text scaling

- Flutter 3.44's `Typography.material2021` (englishLike), size / weight / letterSpacing / height: bodyLarge 16/400/0.5/1.5, bodyMedium 14/400/0.25/1.43, bodySmall 12/400/0.4/1.33, labelLarge 14/500/0.1/1.43, labelMedium 12/500/0.5/1.33, labelSmall 11/500/0.5/1.45, titleLarge 22/400/0/1.27, titleMedium 16/500/0.15/1.5, titleSmall 14/500/0.1/1.43; `leadingDistribution.even`, alphabetic baseline. Family: Roboto on Android, Segoe UI on Windows, `.AppleSystemUIFont` on macOS — SDK typography.dart (3.44.2).
- Floors: body text ≥12 sp (developer.android.com accessibility foundations, 2023-05-08); `labelSmall` (11/500) only for short labels and metadata; Apple 11 pt minimum, 17 pt default (macOS 13 pt default, 10 pt minimum); avoid Ultralight, Thin and Light at small sizes — HIG typography.
- Hierarchy comes from colour and weight before size; a complex surface uses at most 3 sizes and 3 contrast levels; run the squint test — NN/g visual hierarchy (2021-01-17), HIG typography. M3 Expressive "emphasized" roles raise weight only (Medium for display, headline, titleLarge and body; Bold for titleMedium, titleSmall and the labels; the token file is still provisional) — in 3.44 that is `copyWith(fontWeight:)` on the base role, which never changes a line height.
- Android 14+ scales text non-linearly up to 200 %: the AOSP table at 2.0 maps 8→16, 11→22, 14→26, 16→28, 22→35, 100→100 (sp values are not additive; line heights in sp) — developer.android.com Android 14 features; AOSP `FontScaleConverterFactory`. Flutter follows the curve through `TextScaler` since 3.16 on device; `TextScaler.linear` in tests is linear, so a "2.0" render over-sizes large roles unless a `TextScaler` subclass implements the table (§9).
- `textScaleFactor` deprecated since 3.16: `MediaQuery.textScalerOf`, `textScaler.scale(size)`, `MediaQuery.withClampedTextScaling(minScaleFactor:, maxScaleFactor:)`, `withNoTextScaling` for icon fonts — docs.flutter.dev deprecate-textscalefactor.
- WCAG 1.4.4 (AA, F69): content text resizes to 200 % without loss of content or function; Apple asks for at least 200 % (Dynamic Type Body 17 pt → 23 pt at xxxLarge → 53 pt at AX5). Clamp only chrome that has an alternative, and say in the spec what wraps, stacks or clamps at 1.3, 1.4 and 2.0.
- `TextStyle.height` fixes the line box at `fontSize × height`; without it the font's metrics decide (SDK Roboto ≈1.172 em). The theme's `labelSmall` line (1.45) is taller than a `bodyMedium` at 1.1, so anything that shares a line or a baseline row sets `height` explicitly — the 2026-10-21 pill lesson (a two-line heading pill reached 48.1 px at the 1.4 clamp without it).

## 5. Material 3 in Flutter 3.44 — what exists and what does not

- `ThemeData()` is Material 3 by default. `ColorScheme` has 46 current roles (49 fields, 3 deprecated); `fromSeed` defaults to `DynamicSchemeVariant.tonalSpot` (pastel; the seed may not appear), `fidelity` / `content` stay close to the seed, plus monochrome, neutral, vibrant, expressive, rainbow, fruitSalad; 3.27 moved light `on*Container` roles to tone 30 and chip borders to `outlineVariant`; 3.41 bumped material_color_utilities to 0.13.0 — docs.flutter.dev new-color-scheme-roles, material-color-utilities breaking change.
- Custom tokens: a `ThemeExtension<T>` with a const constructor, `copyWith` and `lerp`, registered in both themes; `Theme.of(context).extension<T>()`.
- **M3 Expressive is not in the SDK.** Material and Cupertino froze at the 3.44 cutoff (2026-04-07); new work lives in `material_ui` / `cupertino_ui` (1.0.0 on 2026-08-12; `StyleVariant` 1.2.0, Expressive `IconButton` 1.5.0, `MaterialShapes` with morphing 1.8.0 ≈2026-10-20), and from 1.4.0 they need Flutter 3.47 / Dart 3.13 — out of reach on 3.44 (github.com/flutter/flutter#168813, #184093; pub.dev material_ui changelog). So there are no button groups, split buttons, FAB menu, loading indicator, docked or floating toolbars, spring `MotionScheme` or emphasized roles: a spec expresses those ideas with existing widgets and explicit overrides, or flags a custom widget.
- Chips (SDK 3.44.2 chip.dart; M3 tokens v6_1_0): 32 dp container, radius 8 (the "small" token), `labelLarge`, 18 dp icons (24 dp avatar on input chips), padding 8, `labelPadding` from 8 down to 4 as the label scales 14→28, 8 dp apart; flat chips a 1 dp `outlineVariant` side; selected filter and input chips fill `secondaryContainer` with a transparent side; the elevated variant sits on `surfaceContainerLow` at elevation 1. Assist = contextual action (label `onSurface`); suggestion, input and unselected filter labels `onSurfaceVariant`; assist and suggestion icons `primary`. A pill radius on a chip is a deliberate departure from the token (ANTA's suggestion pills, `StadiumBorder`, 2026-10-21).
- Buttons: `IconButton` M3 minimum 40×40, padding 8, icon 24, `StadiumBorder`, the tap target from the theme; Filled, Text and Outlined follow `visualDensity`; `ButtonStyle.side` replaces a shape-baked side only when the resolved side is non-null (always for `OutlinedButton`).
- Tokens v6_1_0: corners 4 / 8 / 12 / 16 / 28 / full; AppBar 64; NavigationBar 80; BottomSheet max width 640 with a 32×4 handle (an SDK default, not a docs rule).
- Motion in the SDK: `Durations.short1` (50 ms) … `extralong4` (1000 ms) and `Easing.standard`, `emphasized`, `emphasizedDecelerate`, … (material/motion.dart). M3E springs — standard spatial damping 0.9 at stiffness 1400/700/300, expressive 0.6/0.8/0.8 at 800/380/200, effects damping 1.0 at 3800/1600/800 — are Compose practice (androidx MotionScheme tokens v0_14_0) and would map to `SpringDescription.withDampingRatio` if ever wanted. A keystroke-driven surface uses a standard or fast effect, never a bounce.
- Reduced motion: Android "Remove animations" → `MediaQuery.disableAnimationsOf`; iOS sends `reduceMotion` separately; a MediaQuery override does not shorten framework animations by itself — api.flutter.dev disableAnimations.
- `WidgetStateProperty` replaces `MaterialState*` (deprecated after 3.19): `.fromMap` with `&`, `|`, `~` and `WidgetState.any`; the first matching entry wins; a non-nullable map with no match throws.
- 3.44 deprecates `cacheExtent` / `cacheExtentStyle` on scroll views for `scrollCacheExtent` (`ScrollCacheExtent.pixels` / `.viewport`); 3.38 made `PredictiveBackPageTransitionsBuilder` the Android default (450 ms; `TransitionDurationObserver.pumpPastTransition` in tests); 3.44 `ListTile` reports a `FlutterError` in debug when a coloured `Container` sits between it and its `Material` (fails widget tests).
- Lints: `flutter_lints` 6.0.0 (≈2025-05; adds `strict_top_level_inference`, `unnecessary_underscores`), `lints` 6.1.0 adds `use_null_aware_elements` and `no_wildcard_variable_uses`; 5.0.0 dropped `prefer_const_*`. `dart analyze` fails only on warnings, `flutter analyze` also on infos.

## 6. Feedback, focus, gestures

- Ink paints on the nearest `Material`: a decorated `Container` between an `InkWell` and its Material hides the ripple (the suggestion bar's ✕ had none until 2026-10-21); use `Ink`, or a transparent `Material` of its own.
- Pressed, hover, focus and drag use the state layers of §2; a transparent `overlayColor` removes Material's focus overlay; a custom control needs `FocusableActionDetector`.
- Keyboard focus on the desktop builds: a visible indicator is WCAG 2.4.7 (AA); 2.4.13 (AAA) asks for at least a 2 px perimeter at 3:1 change; M3's focus ring is 3 dp in `secondary` and appears only in `FocusHighlightMode.traditional` (touch hides it except in text fields) — in a render set `FocusManager.instance.highlightStrategy = FocusHighlightStrategy.alwaysTraditional` before requesting focus. Focus must not be entirely hidden by sticky bars, sheets or overlays (2.4.11, AA).
- Pointer: 2.5.2 (A) trigger on the up-event or allow abort/undo; 2.5.7 (AA) every drag has a single-pointer alternative (tap-to-select then tap a target, move up/down actions) — ANTA's reorder rows and swipe actions; 2.5.1 (A) path gestures need a single-pointer alternative; 2.5.3 (A) Label in Name — the accessible name contains the visible label.
- Status messages 4.1.3 (AA): snackbars and saved states are announced without moving focus → `liveRegion`, or `SemanticsService.sendAnnouncement(View.of(context), message, textDirection)` (`announce` deprecated since 3.35; Android deprecates announcement events; check `MediaQuery.supportsAnnounceOf`).
- Content on hover or focus 1.4.13 (AA): dismissible, hoverable, persistent — tooltips on desktop.
- Haptics: unspecified in ANTA today; `HapticFeedback` per Android's haptics principles (confirm or reject, long-press) — a gap noted 2026-10-21.
- Toolbars that hide on scroll stay visible under TalkBack (MDC disables `HideViewOnScrollBehavior`); every icon-only action has a name (tooltip).

## 7. Semantics and accessibility APIs (Flutter 3.44.2)

- `Tooltip` is a valid accessible name: on API 28+ the Android bridge sets `setTooltipText` and uses it as `contentDescription` when the node has no label; `labeledTapTargetGuideline` accepts a label or a tooltip.
- `MergeSemantics` joins labels with newlines and gives the actions to the first tappable node in tree order; `ExcludeSemantics` for decoration (a glyph beside text, an avatar, a matrix); `Text(semanticsLabel:)` wraps its own `Semantics` node (SDK text.dart) — harmless as a sibling, but it doubles `find.ancestor(matching: find.byType(Semantics))` counts in tests.
- Headings: `headingLevel > 0` maps to `View.setHeading(true)` on Android; `header: true` alone is not a TalkBack heading and becomes a no-op on both platforms in 3.47 — use `headingLevel`.
- `Semantics(identifier:)` → Android resource-id, iOS accessibilityIdentifier; never announced; `find.bySemanticsIdentifier` in tests (ANTA's `SemanticsIds`).
- 3.44 adds `role` (`SemanticsRole`), `controlsNodes`, `validationResult`, `inputType`, traversal identifiers; `testWidgets` enables semantics by default; `find.semantics.byLabel` / `byPredicate` assert on the merged tree; `isSemantics(isButton:, hasTapAction:, label:)` pins one node per control.
- Descriptions convey purpose, not visuals ("Submit", not "Submit button"), are unique within a list; decorative elements are hidden; plain `Text` needs no extra description — developer.android.com accessibility/apps (2026-09-22).
- What a widget test cannot prove: merged-node reading order, TalkBack's phrasing of headings and tooltips, live-region timing → the `qa-runner`'s uiautomator accessibility dump and Google's Accessibility Scanner on the device (48 dp targets, contrast).

## 8. Layout rules and the "nothing moves" method

- A flex child in an unbounded main axis asserts (`Expanded` / `Flexible` inside a horizontal scroller); the SDK idiom is `LayoutBuilder → SingleChildScrollView → ConstrainedBox(minHeight) → Column`; `IntrinsicWidth` / `IntrinsicHeight` add a speculative pass (O(N²) worst case); a `LayoutBuilder` cannot report intrinsics or a dry layout.
- An intrinsic-width chip inside a scroller: `ConstrainedBox(minHeight)` + `Center(widthFactor: 1, heightFactor: 1)`; a 48 px hit target around a 40 px body through `TapTargetPadding` (a hit anywhere in the band forwards to the child's centre).
- `Row(crossAxisAlignment: CrossAxisAlignment.baseline)` requires `textBaseline` (asserts otherwise); children without a baseline are top-aligned; a concealed 0.01 px leading span does not move the paragraph's baseline.
- Clip: `Clip.none` by default; `hardEdge` fastest, `antiAlias` slower, `antiAliasWithSaveLayer` very slow (dart:ui `Clip`); prefer `borderRadius` on a decoration; never clip inside an animation.
- Reflow WCAG 1.4.10 (AA): usable at 320 CSS px without two-dimensional scrolling — ANTA designs at 360 and tests 360 × 780. Window size classes: compact < 600 dp, medium 600–839, expanded 840–1199, large 1200–1599, extra-large ≥ 1600 (developer.android.com, 2026-09-22) — lay out from the window size, never the device type; do not lock orientation (Android 16 ignores it at sw600dp+ for apps targeting API 36).
- The state matrix: a spec lists every state (empty, one, many, the longest de string, error, disabled, selected, focused, pressed, keyboard up, 2.0×, dark) and the geometry that must not change across them; the reviewer asserts it with `tester.getRect` / `getSize` before and after each state change, never by eye. A bar that lays a session over a hidden normal row (`Positioned.fill` + `Visibility(maintainSize: true)`) keeps its height by construction — there the overflow exception is the guard, not the height assertion.
- Rebuild hygiene: const widgets, widgets over helper methods, `MediaQuery.sizeOf`-style selectors over `MediaQuery.of`, `RepaintBoundary` around self-changing subtrees, `ValueListenableBuilder` / `buildWhen` with a static `child`.

## 9. Rendering and measuring a surface in tests (`render-recipe.md` holds the code)

- `flutter test` runs `flutter_tester` with software rendering, deterministic Skia, `--use-test-fonts --disable-asset-fonts`: an unregistered family falls back to the FlutterTest box font (ascent 0.75 em, descent 0.25 em against Roboto's 0.928 / 0.244 — a bodyMedium baseline at 13.5 instead of 14.8 px). Load Roboto (regular, medium, bold, italics) and `MaterialIcons` from `<sdk>/bin/cache/artifacts/material_fonts` through `FontLoader` under exactly those family names before the first pump; emoji, Noto fallbacks and ro diacritics outside Roboto's coverage are absent — judge glyph coverage on the device.
- Shadows are off: `AutomatedTestWidgetsFlutterBinding` sets `debugDisableShadows = true` (flutter_test binding.dart), so cards, menus and elevated chips render flat. Depth is never judged from a render.
- `defaultTargetPlatform` is android under `flutter test` whatever the host. `tester.view.physicalSize` + `devicePixelRatio` (the default view is 800×600 logical) with `addTearDown(tester.view.reset)`; the keyboard and system bars are `tester.view.viewInsets` / `viewPadding` (`FakeViewPadding`, physical px; the IME is ≈300–350 dp on a Pixel 9 Pro; gesture and 3-button navigation differ in bottom padding).
- Text scale: `TextScaler.linear(2.0)` is linear; device parity needs a `TextScaler` subclass with the AOSP 200 % table (§4). A surface's own clamp (`withClampedTextScaling`) applies inside the render too.
- Goldens: `matchesGoldenFile` captures the first `RepaintBoundary` ancestor, pixel-exact through `LocalFileComparator`; on failure it writes `masterImage`, `testImage`, `isolatedDiff` and `maskedDiff` under `failures/` — Read those instead of eyeballing two renders. Goldens differ across OS, Flutter version and renderer: they are local evidence, never committed.
- Reading PNGs: Claude Code resizes images to fit 2000×2000 px before sending, so a 1080×2400 render loses pixel detail — crop with `magick in.png -crop WxH+X+Y +repage -filter point -resize 300% out.png` (ImageMagick 7.1.2 is `magick`; `convert` on Windows is the NTFS volume tool). Vision judges hierarchy; numbers come from `tester.getRect` / `getSize`, `RenderParagraph` / `TextPainter` metrics and tokens; tolerances are ±1 dp, because a device resolves Roboto through the system font manager (variable axes since 3.41) and line metrics can differ by a pixel.
- Accessibility matchers: `meetsGuideline(androidTapTargetGuideline)` 48×48, `iOSTapTargetGuideline` 44×44, `labeledTapTargetGuideline` (label or tooltip), `textContrastGuideline` (4.5, or 3.0 at ≥18 or bold ≥14; naive pixel estimate; `Text` / `EditableText` only; links skipped) — docs.flutter.dev accessibility-testing. None run in ANTA's suite as of 2026-10-21: the `design-reviewer` reports the gap per surface.
- Motion: a static render cannot judge it; pump fixed intervals and golden each frame, or assert the `AnimationController`'s duration and curve against `Durations` / `Easing`.
- The Widget Previewer (`@Preview`) is experimental in 3.44 (stable in 3.47) and runs on Flutter Web (no `dart:io`, no ffi); the Dart MCP server exposes `widget_inspector`, `get_runtime_errors`, `hot_reload`, `flutter_driver_command` and no screenshot tool; `qa screenshot` remains the device truth.

## 10. Review method, severity and the spec format

- Matrix: text scale 1.0 / 1.3 / 2.0 × light / dark × en / de (the longest locale; strings under 10 characters grow 200–300 % — W3C i18n text-size) × 360 wide (plus 360 × 780) × desktop density for the Windows and macOS builds. 1.3 is a heuristic step (Flutter's `NavigationBar` clamp), not an Android one.
- Heuristics: Nielsen's 10 (reviewed 2024-01-30) for interaction; visual hierarchy = colour and contrast, scale, grouping; at most 3 sizes and 3 contrast levels; the squint test; weak signifiers cost 22 % more time and 25 % more fixations (NN/g 2017-09-03) — flat chrome is safe only with low density, a conventional layout and standout key controls together.
- Severity: NN/g 0–4 (0 not a problem, 1 cosmetic, 2 minor, 3 major, 4 catastrophic; frequency × impact × persistence). Each finding names the rule it is judged against (spec / app rule / WCAG SC / Android / Flutter default) and the render or measurement that shows it, CONFIRMED by a tool result or PLAUSIBLE by reading. Claude reviewers take "only report high severity" literally — ask for everything, filter afterwards (platform.claude.com prompting guides, 2026).
- The spec format (M3's per-component Specs tabs are the model: anatomy, measurements, colour roles per state): tokens by role (`colorScheme.outlineVariant`, `MarkdownBarMetrics.x`), never hex or px literals; per-state values (enabled, pressed, focused, selected, disabled, error); per-scale behaviour (what clamps, wraps or stacks at 1.3, 1.4, 2.0); semantics (label, role, headingLevel, identifier); tolerances; must-not-change geometry; and a lettered list of the defaults the designer chose, for the owner to confirm or reverse.
- The design agents never grade their own work: the `designer` specifies and may re-render once as evidence; the `design-reviewer` runs later, in a fresh context, with the spec, the diff and the states only; the code `reviewer` keeps correctness. `flutter test` runs one at a time, so the lead runs designer → implementer → reviewer and design-reviewer → qa-runner in sequence.

## 11. Platform awareness

- Android 16 / API 36 (Play deadline 2026-08-31, extension to 2026-11-01; developer.android.com behavior-changes-16, 2026-10-16): edge-to-edge without opt-out; predictive-back system animations on by default, `onBackPressed` / `KEYCODE_BACK` no longer dispatched → `PopScope(canPop:, onPopInvokedWithResult:)`, `Form.canPop`, `NavigatorPopHandler`; orientation and resizability locks ignored at sw600dp+ (the opt-out ends at API 37); "outline text" replaces high-contrast text and does not reach Flutter text.
- iOS 26 Liquid Glass (HIG Materials 2025-06-09, updated 2025-09-09): a functional layer for controls, never used in the content layer, used sparingly; the regular variant for text-heavy components. Apple added emphasized weights to every Dynamic Type style (HIG change log 2025-12-16) and asks for 200 % text enlargement.
- Windows: Flutter desktop shrink-wrap targets and compact density; Fluent targeting guidance (learn.microsoft.com guidelines-for-targeting) not yet folded in — a gap noted 2026-10-21; keyboard traversal through `FocusTraversalGroup` with the default `ReadingOrderTraversalPolicy`, `MouseRegion` + `SystemMouseCursors.click` for pointer affordance — docs.flutter.dev adaptive-responsive/input (2026-09-29).
- Compose / MDC-Android is the reference for M3 Expressive metrics whenever the owner asks for an Expressive look: docked toolbar 64 dp on `surfaceContainer` with square corners, floating toolbar 64 dp fully rounded 16 dp from the edge (androidx DockedToolbarTokens 14_0_0, FloatingToolbarTokens 12_0_0); the 80 dp bottom app bar is "still available, but not recommended".
