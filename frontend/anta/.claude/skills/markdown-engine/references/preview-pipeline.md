## Markdown Preview Pipeline
**Deprecated since 2026-09-03, gated by `SettingsKeys.previewModeEnabled` (default off, Settings → "Deprecated features").** The live editor is the only default surface; the page computes `_canPreview = _previewModeEnabled || !_liveMarkdownRendering` (raw-editor users keep the toggle) and, when it is false, never mounts `MarkdownPreviewBlocView`, never pushes content to the bloc, hides the eye button and forces `previewWhenKeyboardHidden` off. Saved `isPreviewMode` positions are masked by `_canPreview` at read time. Share/export lives in the toolbar utility section in both modes. The page is `RouteAware` on `AppNavigator.routeObserver`: `didPopNext` re-reads every editor flag through `_reloadSettings` (the same bundle read `initState` issues; settings are reachable from the editor's drawer), which must never re-apply the saved preview mode — only the position-restore callback on open does that. Two editors over one note are survivable since 2026-09-06 (Session 9 review, C1 — `[[A]]` → `[[B]]` → `[[A]]` pushes a second page for A, and so does search): a page adopts only the `OptimizedNoteContentLoaded` it asked for (`_awaitingContentLoad`, raised at its own `LoadNoteContent` dispatch — the one app-wide bloc emits to every mounted editor and the id guard alone cannot tell two pages for one note apart; deliberately not `ModalRoute.isCurrent`, because a launch restore pushes the whole stack at once and a page may be covered when its first content arrives), and `didPopNext` also runs `_reloadContentIfChanged`, which re-reads the note through `NoteStorageService.loadNoteWithContent` only when the page has nothing unsaved (`didPushNext` force-saved on the way out) and adopts the text through the same `_adoptLoadedContent` path as the first load with the caret re-placed at its clamped (line, column) — never when the content is equal, so an unchanged round trip costs neither caret nor undo history. Saved-position restore is triggered by whichever of content load / position load finishes last. `SimpleMarkdownPreview` and `MarkdownInlineText` (event sheets, agenda, shortcut editor) consume `LineBasedMarkdownBuilder` directly and are unaffected by the flag. The layering below still holds for the gated path:

The note-editor preview is fully BLoC-driven. Keep this layering intact:

```text
OptimizedNoteEditorPage
  -> MarkdownPreviewBloc (lib/bloc/markdown_preview/)
     -> MarkdownRenderService (lib/services/markdown_render_service.dart)
        -> LineBasedMarkdownBuilder (lib/utils/line_based_markdown_builder.dart)
           -> MarkdownChunker (lib/utils/markdown_chunker.dart)      // block scan + chunk layout
           -> MarkdownListSyntax (lib/utils/markdown_list_syntax.dart) // shared list grammar
  -> MarkdownPreviewBlocView (lib/widgets/markdown_preview_bloc_view.dart)
     -> SourceMappedMarkdownView (lib/widgets/source_mapped_markdown_view.dart)
```

Non-negotiable invariants:

- Bloc state is `Equatable` and contains only primitives + a `renderHandle: int` token. Never put `InlineSpan` trees, builders, or other heavy objects in state.
- Spans are pulled from `bloc.renderService.builder` on demand; the widget rebuilds the heavy list only when `renderHandle`, `linesPerChunk`, or `fontSize` change (`buildWhen`).
- The bloc owns its `MarkdownRenderService` and `PreviewScrollController` and disposes them in `close()`. The page wires callbacks via `bloc.bindCallbacks(onLinkTap:, onCheckboxTap:)`.
- **Content sync**: use `bloc.bindContentProvider(() => _contentController.text)` once in `initState` and call `bloc.markContentDirty()` on every keystroke (free `int++`). Dispatch `PreviewContentRefreshRequested` (not `PreviewContentChanged`) when you want a lazy refresh; the bloc short-circuits when the dirty version hasn't moved since the last consume. Only use `PreviewContentChanged` for eager pushes (toggle, checkbox, locale change, content load).
- **Live refresh**: `_scheduleLivePreviewRefresh()` (called from `_onTextChanged`) debounces `PreviewContentRefreshRequested` at 500 ms for non-large notes (`lineCount <= AppConstants.previewPreloadLineThreshold = 3000`). It is gated on `!_isLoading` and `state.hasTheme` so the first build is never blocked. The debounce timer is cancelled in `dispose()`.
- **Search content sync**: `_pushPreviewContent` calls `_searchController.updateContent(content)` when `_searchController.isSearching`; `_scheduleLivePreviewRefresh` does the same after dispatch. Never call `updateContent` inside `build()`. `ReEditorSearchController.updateContent` deduplicates on `identical/==` so redundant calls are free.
- Theme dispatch (`PreviewThemeChanged`) happens from `MarkdownPreviewBlocView` lifecycle hooks (`didChangeDependencies` + a `DevOptions` listener) — never from `build()`. Equality is keyed on `(brightness, debugEnabled)` so closure-only changes do not trigger rebuilds.
- Scroll progress bypasses the bloc event queue: the view calls `bloc.scrollController.updateProgress(progress)` directly to avoid per-frame state churn.
- **Preview view key**: `MarkdownPreviewBlocView` creates its own `GlobalKey<SourceMappedMarkdownViewState>` and binds it into the bloc's scroll controller on mount, reusing a key that is already bound so a remount keeps targeting the live state; the page holds no preview key (2026-09-04) and reads the view through the scroll controller (`currentLineIndex`, `progress`, the scroll facades).
- **Preview→editor scroll**: on toggle back to editor, compare the scroll controller's `currentLineIndex` against `renderService.chunkStartLineForLine(savedBaseIndex)` to detect real user scrolling. Chunks are block-aligned (variable line counts), so never assume `lineIndex ~/ linesPerChunk` — always resolve a chunk's start line through the builder/service. Only snap the editor and move the caret when the user actually moved the preview; otherwise fall back to `_restoreEditorPosition()` which honors the exact saved selection.
- **Toolbar helper**: `_buildMarkdownBar()` is the one `MarkdownBar(...)` tree, built only for the loaded note view. There is no loading skeleton any more (2026-09-07): while `_isLoading` the body is blank, and the finished body — stats bar, editor, toolbar — fades in once through an `AnimatedSwitcher` over `AppConstants.animationDuration`. The old skeleton built the bar from default settings with the paste/share/counter buttons missing and no bottom spacing, so it reflowed twice on every open.
- **Double-tap from preview**: `_handleDoubleTapLine` parks the cursor at end-of-line. `DoubleTapLineDetector` currently always passes `columnOffset = 0` (column resolution from styled spans needs `TextPainter` introspection — future work). Forward-compatible: when a future detector passes `columnOffset > 0`, the handler clamps it to the line length.
- Adaptive chunk sizing lives in `MarkdownChunker.adaptiveChunkSize` (capped at `maxAdaptiveChunkSize = 100`) so `scrollToLineIndex` precision stays usable on huge notes. The render service applies it before constructing the builder; the builder then receives the final per-chunk target.
- The empty-preview placeholder text is locale-cached on the page (`_emptyPreviewPlaceholder`) and re-dispatched when the locale changes while the note is empty.
- Preview hyperlinks: the page passes `_handleLinkTap` to `MarkdownPreviewBlocView.onTapLink`. The handler validates the scheme against `_allowedLinkSchemes` (`http`, `https`, `mailto`, `tel`), launches via `url_launcher` in `LaunchMode.externalApplication`, and shows a localized `CustomSnackbar.showError` (`linkSchemeNotAllowed` / `linkOpenFailed`) on rejection or failure. Do not bypass scheme validation. Wiki links (2026-09-06, Session 9): `[[title]]` renders on both surfaces as a tinted, underlined title (brackets concealed in the editor, dropped in the preview) and both surfaces hand the raw title to the page's `_handleWikiLinkTap` (`ModernEditorWrapper.onOpenWikiLink`, `MarkdownPreviewBlocView.onTapWikiLink`, `SimpleMarkdownPreview.onTapWikiLink`), which trims it, resolves it through `NoteStorageService.resolveNoteByTitle(title, preferFolderId: widget.folderId)` — never the repository or a DAO from the page, never on the render path — shows the neutral `wikiLinkNoteNotFound` snackbar on a miss (the title elided by `WikiLinkTitle.forDisplay`), does nothing for a link to the open note itself, bails if the page is no longer the current route (two rapid taps push one editor), and otherwise saves the position and pushes the editor with the resolved metadata. The calendar's `EventDetailSheet` (read-only) pops with no action first and then hands the title to the calendar page's `_openWikiLink` (no folder preference); the event editor sheet, the shortcut editor preview and the agenda's `MarkdownInlineText` render wiki links inert, like their `[text](url)` links.

## Markdown Block Model And Chunking
`lib/utils/markdown_chunker.dart` is the single source of truth for how note content is divided into render chunks. Both the preview renderer **and** the editor's debug chunk overlay consume it, so their chunk boundaries are guaranteed identical.

- `MarkdownChunker.computeLayout({lineCount, chunkSize, lineAt})` returns a `MarkdownChunkLayout` = `{ blocks: List<MarkdownBlock>, chunkStartLines: List<int> }`. It runs one O(n) forward scan.
- `MarkdownBlock { kind, startLine, endLine, atomic }` models **multi-line** blocks only (today: `MarkdownBlockKind.codeFence`, including an unterminated fence that runs to EOF, and `MarkdownBlockKind.callout` — a `> [!TYPE]` lead plus every contiguous blockquote line, stepped by `MarkdownCalloutSyntax.blockStep`, the same per-line transition the editor's positional callout pass in `MarkdownEditorLineIndex` uses, so the two block extents cannot differ). Single-line content (paragraphs, headings, list items, blockquotes, rules, single table rows) is **implicit** — never modeled — so the block list stays O(number of multi-line blocks), not O(lines).
- Chunk boundaries are **block-aligned**: `atomic` blocks are never split across a chunk; non-atomic blocks (code fences) may be split so very large code blocks keep virtualizing. When you add a single-widget block type (table, math), set `atomic: true` and chunking keeps it whole automatically — the preview and the editor overlay both inherit the alignment.
- The builder exposes block-aware helpers used everywhere instead of `lineIndex ~/ linesPerChunk`: `chunkStartLine(i)`, `chunkLineCount(i)`, `chunkIndexForLine(line)` (binary search), and `_blockForLine(line)` for code-fence membership (replaced the old per-chunk code-block state caches). `MarkdownRenderService.chunkStartLineForLine(line)` is the service-level convenience for the page.
- The recursive inline parser (`_parseInline`) is offset-preserving: every leaf text run is routed through `_applyHighlighting` with its exact source offset, so search highlights stay aligned through nested emphasis, links, escaping, and ghost/list content. When adding inline syntax, keep this contract — never break the source-offset threading.
- **Inline grammar (2026-09-04)**: `_parseInline` and the editor's `EditorInlineEmitter.append` are emitters over `MarkdownInlineGrammar.tokenize` (`lib/utils/markdown_inline_grammar.dart`) — one CommonMark-style tokenizer (delimiter-stack pairing with the rule of three, matched-length backtick fences, `___`, escapes, ghosts and code spans as opaque atoms, links/wiki links/colours/tags/URLs placed through their own modules) that returns top-level tokens for a `[start, end)` range and reads nothing outside it, so the preview's substrings and the editor's ranges tokenize identically. Consumers recurse into container ranges with `depth + 1`; past `maxNestingDepth` the tokenizer returns only the range's ghost runs (a ghost is a placeholder, never styling — it stays concealed on both surfaces at any depth, Session 4 review 2026-09-05), so both surfaces flatten at the same point. Delimiter pairing carries CommonMark's `openers_bottom` bound (24 slots: char × run length mod 3 × closer-can-open, allocated lazily on the first failed search), so a 4 k-char line of unpairable runs pairs in ~65 µs instead of ~1 ms; bare URLs give a trailing `*` `_` `~` back to the emphasis (`MarkdownLinkPatterns.isTrailingPunctuation`, GFM), never `=`. Since 2026-09-06 (Session 9) the tokenizer also places `[[title]]` wiki links (`MarkdownLinkPatterns.matchWikiLinkAt`, probed on a doubled `[` before the link rule; a construct with any atom inside is literal; the title is literal — the lookup key — and never a nested range). The wrapper's tap zones resolve through `EditorInputPolicy`, which takes one `linksAndTags` descent per tap — the whole-line walker that returns every link, wiki link and tag `tokenize` renders, at any nesting depth, outermost first — and reads link / wiki link / tag off it as the first token of that kind whose `containsStrict` holds; `linkAt`/`wikiLinkAt`/`tagAt` are that rule in offset form. One descent, so the offset form and the range form cannot disagree; a caller that already has the line's ghost runs passes them in rather than paying for a second scan. Headings and horizontal rules come from `MarkdownLineShape.headingAt` / `isHorizontalRule` on every surface (preview, editor, line-height calculator, paste policies). `test/utils/markdown_inline_agreement_test.dart` renders a corpus through both builders and compares the visible text + per-character style, so a grammar change that lands on one surface only fails there.
- **Plain text is the third emitter (parity pass, 2026-09-07)**: `MarkdownPlainText.strip` (`lib/utils/markdown_plain_text.dart`) is what `NoteMetadata.generatePreview` — and therefore the stored `notes.preview` column, the row's second line, quick search and the FTS mirror — reads: every line of the note, markers gone, whitespace collapsed, capped at 200 with an ellipsis. It composes the same modules the two render surfaces do and owns no pattern of its own: fences through `MarkdownChunker.isFenceDelimiter`, rules / table shapes / headings through `MarkdownLineShape`, quote markers and callout leads through `MarkdownCalloutSyntax` (the lead becomes its label), list markers through `MarkdownListSyntax.parse` (a checked task prefixes `✓ `; no recursion after the marker, so `- - x` keeps its literal second dash exactly as the editor paints it), money rows through `MarkdownMoneySyntax` (label and the literal amount, never a folded balance), and everything inline through `MarkdownInlineGrammar.tokenize` with the same nested-range recursion — escapes to their character, code / emphasis / colour to their inner text, links to their text, wiki links to their title, ghosts to nothing. A note that strips to nothing falls back to the raw whitespace collapse. Backup restore runs the same function (`backup_service.dart`), so a restored row never carries a second preview shape. Existing rows keep their old text until their next save — a lazy recompute, no migration — and because quick search reads the column, a marker-containing query (`**`, `[[`) stops matching a row once it is re-saved (decision C11).

## Markdown Lists
`lib/utils/markdown_list_syntax.dart` (`MarkdownListSyntax`) is the **single source of truth** for list grammar, shared by the editor and the renderer so they can never disagree about what is a list.

- `MarkdownListSyntax.parse(line) -> MarkdownListItem?` classifies a line as `MarkdownListKind.{bullet, ordered, task}` and returns the indent string, marker, ordered delimiter (`.` or `)`), checked state, the `[` bracket column (tasks), the content-start column, and the content text. All columns are line-relative; the renderer adds the line's source-start offset for absolute positions. Detection order is task → bullet → ordered.
- Supported (GFM): `-`, `*`, `+`, `•` bullets; `N.` / `N)` ordered; `- [ ]` / `- [x]` tasks (markers `-`, `*`, `+`). `indentLevel` counts columns (tab = 2) and divides by `indentUnit = 2`.
- The editor (`MarkdownListUtils`) delegates all detection to `MarkdownListSyntax`: `getListPrefix` (Enter-continuation — preserves indentation, continues tasks unchecked, increments ordered numbers keeping the delimiter), `isEmptyListItem` (terminate list on Enter), `isListLine` (Tab/Shift-Tab gating).
- The renderer's `buildLine` calls `MarkdownListSyntax.parse(line)` once and dispatches to `_buildCheckboxLine` / `_buildListItem` / `_buildOrderedListItem`. Nesting is a width-based `Padding` (`level * baseFontSize`), never literal spaces; bullets cycle `• ◦ ▪` by depth through `MarkdownListSyntax.bulletGlyph(level)` — the one glyph function, read by the preview, the live editor's list branch and both surfaces' bulleted money rows (2026-09-05; each glyph is one UTF-16 unit so the editor substitutes it 1:1). Do **not** reintroduce a second list regex anywhere — extend `MarkdownListSyntax`.
- Editor companion: `ModernEditorWrapper` overrides re_editor's `CodeShortcutIndentIntent` / `CodeShortcutOutdentIntent` via `CodeEditor.shortcutOverrideActions` so **Tab / Shift-Tab** indent/outdent a whole list item by `indentUnit` spaces when the caret is on one; non-list lines fall through to re_editor's default `applyIndent()` / `applyOutdent()`.
