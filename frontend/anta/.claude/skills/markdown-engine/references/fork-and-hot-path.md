## From "re_editor fork (`packages/re_editor/`)"

Local perf-tuned fork, **owned** since the Session 7a sync (2026-09-04): its API is whatever the app needs, so fork members may be added, renamed or removed when a feature calls for it; upstream (`reqable/re-editor`, last evaluated at `28d9fc0`) is watched, not tracked, and cherry-picks are one-off decisions against the table in `docs/re-editor-performance-2026-07.md`. No nested `.git` under it — the outer repo is its only history (upstream base `dfbca60`, `m0b-x/re-editor` `main`; provenance in COPILOT_CONTEXT "Generated And Local Package Notes"). Preserve: `CodeLines.asString` 2-slot round-robin cache; `_hashCache` short-circuit comparisons; delta-maintained `_lineCount`/`_charCount` in `_CodeLineSegmentQuckLineCount` mutators and its count-carrying full-range `clone` (no `fold` on any mutation path — `test/utils/code_lines_sharing_test.dart` pins it); binary-search paragraph lookups in `_code_field.dart`; the bounded paragraph LRU `_kMaxCacheSize` (128 since 2026-09-04 — measured: 512 cost ≈15 MB more native heap on a 10k-line note; re-measure before changing) and the 128-entry marker-measurement LRU in front of the hanging split; 50 ms highlight debounce; new `CodeLines` mutation paths must call `cloneShallowDirty()` (never the public constructor); app code never rebuilds a document with `CodeLines.of([...])` — a single-line edit is `CodeLines.replaceLine(index, line)` and a single-line removal `CodeLines.removeLine(index)`, so every untouched segment keeps its backing-list identity (the line index's dirty flag) and the undo node pins one segment, not the document; the undo history is capped at 200 nodes (`_kMaxUndoHistory`, a hard bound, not a coalescing window) and `undo`/`redo` raise `isRestoringHistory` while they publish, which is how `EditorEditTracker` tells restored text from a paste (2026-09-05); **seeding or swapping a document wholesale is `loadText(text)`, never `set text`** (2026-09-05) — `set text` is a revocable op over the empty document the controller is constructed with, which is how undo used to wipe a freshly opened note; `loadText` resets the history to the loaded text, the cache folds selection-only/composing-only changes into the current node (a tap never enables undo, a caret move after an undo keeps redo), and `test/re_editor/undo_baseline_test.dart` pins it; the controller's `value` setter maps an empty document onto the initial blank line like its `codeLines` setter, so `removeLine` needs no survivor guard; on Android/iOS the editor's bare `Focus.onKeyEvent` handles Backspace/Enter/Tab/Shift-Tab on key-down **and key-repeat** events, Tab through `shortcutOverrideActions` (the wrapper's list-aware indent) after the `readOnly` check (2026-09-05; the desktop `Shortcuts` path filters overrides by the same editable-intent rule, so a read-only editor never runs the app's indent) — keep it, or a physical keyboard's Tab leaves the editor. Fork additions to keep intact: `CodeEditorTapInterceptor` (tap-down claim / tap-up action in `_code_selection.dart`, non-mutating `positionAt` in `_code_field.dart`); `CodeHangingTextSpan` → `_HangingParagraphImpl` (two-paragraph hanging indent; all geometry queries must keep mapping piecewise through marker/content; the indent is the marker's advance **floored** and the boundary offset resolves to it for both affinities; height is the taller part; never built with infinite width; the marker paragraph comes from `_markerMeasurements` keyed by the marker span's value, and the split is rejected when the built marker's `lineCount > 1` — the same arithmetic every consumer reads, never a height ratio; `hangingChars` must fall on a word boundary because `getWord` never crosses the seam; `trucate`/`_dropPrefix` rebuild a split `CodeDecoratedTextSpan` through `_rebuildSplit` so the chip survives — `test/re_editor/hanging_paragraph_test.dart` pins it and `CodeParagraphProviderForTesting` is the seam); the paragraph LRU evicts CLOCK-style (an identity hit flags the paragraph `_recentlyUsed`, a flagged head gets a second lap — plain head eviction walked through the visible lines once per 128 fresh caret-line spans; the 128 bound is untouched); a paint-only `textStyle` change (the theme's `textColor` flip) clears the highlighter cache and relays out, since colour is baked into the cached paragraphs; three debug asserts in `_build` (a scaled root keeps the base `fontFamily`/`height`; every `CodeInlinePaintSpan` fits under the line height; after layout no row of a tree holding a paint span grew past the strut); `CodeInlinePaintSpan` (placeholder run + custom canvas paint after `drawParagraph` — exactly one U+FFFC code unit, substituted 1:1 for one source char, height kept under the strut height; the app's `EditorCheckboxSpan` paints the task checkbox with it, whose indeterminate facet is positional and driven by the span builder's task index alongside the fence index); `CodeDecoratedTextSpan`/`CodeTextDecoration` (rounded chip painted BEFORE the text — tag pills, inline-code chips; reserves no layout space, and `trucate`/`_dropPrefix` must keep untouched subtrees by identity so these spans survive the hanging marker/content split); and the render's screen-reader surface (2026-09-05, Session 7c): `describeSemanticsConfiguration` announces the **visible window** as the text-field value (never `asString`), with `onTap` / `onDidGainAccessibilityFocus` (macOS only since the 2026-09-05 review; focus without keyboard via `consumeKeyboardToken`) / `onSetSelection` and a window-relative `textSelection` that is omitted, never clamped, when the caret is off screen — the handlers sit in `code_editor.dart` and reach the render through explicit callbacks because a `Semantics` widget above a boundary render never merges into it — and `assembleSemanticsNode` adds one keyed child node per interceptor zone (`CodeEditorTapInterceptor.zonesOf` → `CodeEditorSemanticsZone` start/end/label) on the visible lines, whose tap runs `shouldIntercept` then `onTap` at the zone start; the node cache is keyed by line index and **must** be nulled in `clearSemantics()`, or a second platform semantics enable reuses nodes of a disposed owner. Paste flows through the app's `ListAwarePasteController` (`lib/utils/list_aware_paste.dart`, a `CodeLineEditingControllerDelegate`) — list-aware multi-line paste; IME-key paste bypasses it by design (single application confirmed 2026-09-05: the shortcut and the selection toolbar both reach the delegate's `paste()`, the IME path is `edit()` → `_replaceRange` and applies neither transform; `\r\n`/`\r` are normalised twice, in `transform` and in `String.textLines`, so a `\r` never reaches a `CodeLine`). Both paste policies share `MarkdownLineShape.isLineLedConstruct` (`lib/utils/markdown_line_shape.dart`): the width line-breaker (`EditorWidthCalculator.breakLinesSmartly`, run by `PasteLineBreaker` after large insertions) never splits a line-led construct — money row, heading, quote/callout, table row, fence delimiter, horizontal rule — and the list-aware transform never prefixes one with a list marker (money uses the full `MarkdownMoneySyntax.parse`, so plain `$5 coffee` text is not structural). Both are fence-aware since the 2026-09-05 Session 6 review: `ListAwarePasteController` takes `isFenceLine` and leaves a fenced caret line alone; `PasteLineBreaker.run` takes `lineInFenceBody` (from `EditorRenderController`) and seeds `breakLinesSmartly(inCodeBlock: true)` when the pasted range starts inside a fence body, so code pasted into an open fence is never hard-wrapped (the slice alone cannot know — fence-ness is positional); the reflow maps the caret through `LineBreakResult.lastLineSourceOffsets` so it lands where the pasted text ends, not past a pre-existing suffix; the line-break width comes from `controller.options.lineBreak`; and one over-wide line is measured once (`knownExceeds`). `pastedLength` is the *net* growth: a paste over a selection under-covers its range in the safe direction (never a line before the true start) and a shrinking paste is never reflowed — documented on `_startLine`, pinned, not fixed. A paste of exactly `"\n" + indent` is indistinguishable from an Enter and continues the list (pinned); Enter over a non-empty selection continues nothing (pinned). `test/utils/list_aware_paste_test.dart` is the transform's suite. Per-line height: `_CodeParagraphProvider` gives a paragraph whose **root span** sets a fontSize different from the base style its own strut + preferred line height (memoized per size) — this is how editor headers render taller; don't key line-height decisions on anything but the root span's fontSize. Anything anchored to a specific line (caret, selection handles, IME caret rect, toolbar anchors, floating cursor, and the scroll helpers `makePositionVisible` / `makePositionCenterIfInvisible` — the autoscroll behind every edit and the `goToMatch` / position-restore re-centre, whose bottom-edge tests read the caret's *top* and so need the line's own height, 2026-09-05) must use the render's `lineHeightOfLine(index)` / `lineHeightAtOffset(offset)` — never the base `lineHeight` getter, which is only for whole-viewport estimates (scroll math, chunk indicators). The scroll coordinate space above the displayed window is flat by design (`startIndex * base`, real heights folded back through `correctBy`, a capped retry), so the off-window jumps in those helpers estimate from the *last* displayed line and centring subtracts half a viewport — one arithmetic, `_verticalCenteringTarget`, shared since 2026-09-07 with `CodeScrollController.makeCenterIfInvisibleOnLayout`, the layout-time variant (request parked on the scroll controller, consumed by `performLayout` through `correctBy` in a bounded loop, works before the editor is built) that the page uses to open a note with its first frame already on the stored line; the mount gate waits on the position read for it. `CodeScrollController.revealInAncestors(position, {margin, duration, curve})` (2026-09-30) is the ancestor half those helpers leave out — the caret line's rect, clipped to the editor's box, handed to `showOnScreen`, for an editor embedded in a scroll view (the event description cell); it reads the last layout, so call it post-frame, and it returns false for a line the editor has not scrolled to; opt-in, the note editor never calls it (`test/re_editor/reveal_in_ancestors_test.dart`). `CodeFieldRenderForTesting.of(renderObject)` (`code_field_testing.dart`) is the test seam for the three getters and `displayedLineIndices`; `test/re_editor/scroll_to_position_test.dart` and `line_height_contract_test.dart` pin them. Two deliberate exceptions stay flat: `_getHandleDy`'s drag quantum and `floatingCursorHeight` (iOS clamp, sub-line). **Mounting an editor notifies nobody (2026-10-01):** the delegate handoff in `_code_line.dart` used to call `notifyListeners()` on the host's controller from `initState` — mid-build, with nothing changed — so hosts read a mount as an edit and builders above the editor threw "setState() called during build"; it now notifies only a delegate that has listeners of its own, i.e. a controller swapped into a mounted editor (`test/re_editor/controller_handoff_test.dart`). Do not rely on a notification at mount to initialise anything, and do not reintroduce the unconditional call.
