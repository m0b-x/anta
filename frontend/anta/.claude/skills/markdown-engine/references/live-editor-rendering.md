## From "Live editor rendering (`lib/utils/markdown_editor_span_builder.dart`)"

`MarkdownEditorSpanBuilder` renders essential markdown *inside* the re_editor text mode, gated by the "live markdown rendering" editor setting (`SettingsKeys.liveMarkdownRendering`, default true; OFF = plain text + ghost-only rendering). Routing lives in `EditorRenderController.buildSpan` (`lib/controllers/editor_render_controller.dart`, page-owned; it also holds the render-context cache, the money config and the palette, and reports whether `applyMoneyConfig`/`applyPalette` changed anything so the page repaints only then): markdown builder first, the static `ghostSpan` fallback. The renderer is **seven libraries, one responsibility each** (2026-09-04) and app render callers import `markdown_editor_span_builder.dart` alone: the builder itself owns `build()`'s routing and the line shapes (header / quote and callout / rule / list item / table row / fence) — `build()` is a wrapper over the private `_route` carrying one debug assert that the returned span's `toPlainText(includePlaceholders: true)` has exactly the line's code units, the only inventory check that covers the money row, marker runs, chrome runs and paint spans (2026-09-05); display money rows (`needsBalance`) resolve their balance in **both** reveal states, only the memo is skipped on reveal (a reveal build with balance 0 flipped a negative total's label colour on caret entry); the list branch is gated by the allocation-free `MarkdownListSyntax.scanListShape` before `parse` runs (`test/utils/markdown_list_syntax_test.dart` pins the lockstep); `editor_render_context.dart` holds `EditorRenderContext` (style, baseColor, primary, isDark, onAccent) — **no `BuildContext` exists anywhere under `lib/utils/markdown_editor_*`**, the page resolves one context per theme/style generation through `EditorRenderContextCache` (identity check first, then value equality — a value-equal rebuilt `ThemeData` hands back the cached instance) and hands the same instance to every line, and that context is the span memos' generation key (adopting an unequal one drops them); `markdown_editor_span_cache.dart` owns the text-keyed LRU (1024), the positional LRU (128, keyed by the `PositionalSpanKey` record `(tag, value, text)` — never a string interpolation, which copied the line on every hit), the money parse memo (256) and `adoptContext`; `markdown_editor_emitter.dart` (`EditorSpanEmitter`) turns a source range into leaves — ghost split, `concealStyle`/`dimStyle`, `emitChrome`, and the debug code-unit inventory assert; `markdown_editor_inline_emitter.dart` (`EditorInlineEmitter.append`) emits `MarkdownInlineGrammar` tokens and owns the inline styles; `markdown_editor_money_row.dart` (`EditorMoneyRowBuilder.build`) builds the money row; `markdown_editor_paint_spans.dart` holds `EditorMoneyTotalSpan` / `EditorCheckboxSpan` / `EditorCheckboxVisual` / `EditorCalloutIconSpan` (the callout lead's icon, one U+FFFC for the `[`, painter laid out at construction like the money chip). The emitters are **static** — the build path allocates no emitter and captures no closure per line. Invariants:

- Tappable checkboxes and concealed links go through the fork's `CodeEditorTapInterceptor` (built in `modern_editor_wrapper.dart`): the tap is claimed at tap-down inside the editor's gesture pipeline, so the caret never moves, focus is never requested (no keyboard rise on an unfocused editor), and re-taps on the same spot fire every time. The zone rules themselves are the pure `EditorInputPolicy.resolveTap` (`lib/utils/editor_input_policy.dart`, table-tested row by row in `test/utils/editor_input_policy_test.dart` — a new rule goes there, never into the wrapper; `toggledTaskLine`, `listIndent` and the `GhostEngagement` two-tap state machine live beside it), and the wrapper maps the returned `EditorTapAction` to haptics plus the page callback. Zones resolve from line text via the shared grammars once at tap-down (`_claimTapAction` memoises a `_TapClaim`); tap-up (`_consumeTapAction`) reuses the memo when index/offset/line text/selection/fence flag are unchanged, re-resolves otherwise, and always drops it — never let a claim outlive its press. Zones in precedence order: checkbox, link, wiki link (`onOpenWikiLink`, the raw `[[title]]`), money, tag (`onOpenTag`, `#` preserved). Pass-through rules (keep ALL of them): reveal (selection-covered) lines, fence lines, lines over `MarkdownEditorSpanBuilder.maxStyledLineLength`, taps clamped to the line-end offset (blank space), link-construct boundary offsets, escaped/image opens, brackets inside inline-code runs, and **ghosts win** — taps inside a ghost run ride the selection change. Desktop: primary-button only, shift-click passes through, claims are per-pointer, and the outer `ensureInput` is suppressed for claimed taps. One claim is live at a time (2026-09-04, Session 7b): a press arriving while a claim is live is never intercepted and takes the plain path, and on desktop the claiming pointer moving past the slop releases the claim into an ordinary drag selection — the fork replays the tap-down at the original down offset first, so the replay produces the caret and pairing state a plain press there would have produced (a down cell inside an existing selection takes `_selectPosition`'s `_handleByNextEvent` early return and the drag extends from that selection, exactly as a plain press does). Three rules from the 2026-09-05 review: the slop test is **per axis** through `computeHitSlop(kind, MediaQuery.maybeGestureSettingsOf(context))` (the private `_withinHitSlop`) at both the move-release rule and `_finishInterceptedTap`, so a claimed press either fires or becomes a drag exactly where the drag recognizers accept — a euclidean test leaves a sub-pixel diagonal window that releases the claim, moves the caret and fires nothing; a stranded claim (its pointer's up/cancel never reached the `Listener` — capture steal, `PointerRemovedEvent`) is dropped by the next primary press from the same mouse device (`_interceptedTapDevice`); and both deferred `Future(ensureInput)` sites are `mounted`-guarded. `test/re_editor/tap_interceptor_test.dart` (Android path) and `tap_interceptor_desktop_test.dart` pin all of it. Screen readers reach the same zones (Session 7c): `EditorInputPolicy.zonesOf` is the range-enumerating sibling of `resolveTap` (grammar-driven, first-claim-wins per offset in the same precedence, ghost runs cut out; the agreement group in `editor_input_policy_test.dart` pins that every offset resolves identically through both), the wrapper maps each zone's action to one of the five ARB labels (`editorZoneToggleTask` / `editorZoneOpenLink` / `editorZoneOpenWikiLink` / `editorZoneOpenMoney` / `editorZoneSearchTag`, resolved once in `didChangeDependencies`) and hands them to the fork through the interceptor's `zonesOf`. That path runs once per visible line on every semantics flush, so the wrapper answers the three pass-through rules first and memoises the rest per line text (`LruCache`, 256, dropped when the enabled-zone set or any label changes; `debugZoneResolveCount` counts misses) — and the fork's `set semanticsZonesOf` never sees the app's function (`CodeEditor` forwards its own bound method), so an app-side cache must invalidate itself. Zone node ids are keyed by line index: an edit that shifts a zone's line renumbers its node, an accepted TalkBack focus-continuity cost. The render's `onDidGainAccessibilityFocus` is plumbed on macOS only (2026-09-05 review, mirroring `material/text_field.dart` — on Android a TalkBack sweep would take keyboard focus that no lose handler gives back). `test/widgets/modern_editor_wrapper_semantics_test.dart` pins that activating a node toggles the box / opens the link / searches the tag with the caret untouched. A box tap toggles as **one atomic value change with the selection untouched**.
- Ghost taps are modal: the first tap selects the whole run (typing replaces), a second tap on the same unmodified ghost leaves the collapsed caret in place for in-place editing (engagement state clears when the selection leaves the run or the line's text changes; since the 2026-09-05 Session 6 review one arming feeds exactly one caret change — `GhostEngagement._engage` disarms on every bail-out, so a keyboard caret move inside the 350 ms window can no longer select a run — and a collapsed caret parked exactly on a run boundary disengages, matching `containsStrict`). `EditorInputPolicy.listIndent` snaps to the fork's two-column grid exactly like `_applyTextIndent`/`_applyTextOutdent` (so single-line and multi-line Tab agree), derives its unit from `MarkdownListUtils.indentUnit`, and both the wrapper's Tab and `EditorEditTracker`'s Enter continuation pass through on fence lines (`isFenceLine`); Enter with the caret parked right after a list marker splits the item (`- item` → `- `, `- item`) instead of deleting the marker line, and the Enter shape is tested before the paste threshold so a 20-space-deep item still continues. Ordered lists are not renumbered on Enter/Tab and ordered items never take a task box — both deliberate, documented on `getListPrefix` and `MarkdownListSyntax`.
