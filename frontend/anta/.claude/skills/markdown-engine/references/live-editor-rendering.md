## From "Live editor rendering (`lib/utils/markdown_editor_span_builder.dart`)"

`MarkdownEditorSpanBuilder` renders essential markdown *inside* the re_editor text mode, gated by the "live markdown rendering" editor setting (`SettingsKeys.liveMarkdownRendering`, default true; OFF = plain text + ghost-only rendering). Routing lives in `EditorRenderController.buildSpan` (`lib/controllers/editor_render_controller.dart`, page-owned; it also holds the render-context cache, the money config and the palette, and reports whether `applyMoneyConfig`/`applyPalette` changed anything so the page repaints only then): markdown builder first, the static `ghostSpan` fallback. The renderer is **seven libraries, one responsibility each** (2026-09-04) and app render callers import `markdown_editor_span_builder.dart` alone: the builder itself owns `build()`'s routing and the line shapes (header / quote and callout / rule / list item / table row / fence) — `build()` is a wrapper over the private `_route` carrying one debug assert that the returned span's `toPlainText(includePlaceholders: true)` has exactly the line's code units, the only inventory check that covers the money row, marker runs, chrome runs and paint spans (2026-09-05); display money rows (`needsBalance`) resolve their balance in **both** reveal states, only the memo is skipped on reveal (a reveal build with balance 0 flipped a negative total's label colour on caret entry); the list branch is gated by the allocation-free `MarkdownListSyntax.scanListShape` before `parse` runs (`test/utils/markdown_list_syntax_test.dart` pins the lockstep); `editor_render_context.dart` holds `EditorRenderContext` (style, baseColor, primary, isDark, onAccent) — **no `BuildContext` exists anywhere under `lib/utils/markdown_editor_*`**, the page resolves one context per theme/style generation through `EditorRenderContextCache` (identity check first, then value equality — a value-equal rebuilt `ThemeData` hands back the cached instance) and hands the same instance to every line, and that context is the span memos' generation key (adopting an unequal one drops them); `markdown_editor_span_cache.dart` owns the text-keyed LRU (1024), the positional LRU (128, keyed by the `PositionalSpanKey` record `(tag, value, text)` — never a string interpolation, which copied the line on every hit), the money parse memo (256) and `adoptContext`; `markdown_editor_emitter.dart` (`EditorSpanEmitter`) turns a source range into leaves — ghost split, `concealStyle`/`dimStyle`, `emitChrome`, and the debug code-unit inventory assert; `markdown_editor_inline_emitter.dart` (`EditorInlineEmitter.append`) emits `MarkdownInlineGrammar` tokens and owns the inline styles; `markdown_editor_money_row.dart` (`EditorMoneyRowBuilder.build`) builds the money row; `markdown_editor_paint_spans.dart` holds `EditorMoneyTotalSpan` / `EditorCheckboxSpan` / `EditorCheckboxVisual` / `EditorCalloutIconSpan` (the callout lead's icon, one U+FFFC for the `[`, painter laid out at construction like the money chip). The emitters are **static** — the build path allocates no emitter and captures no closure per line. Invariants:

- Tappable checkboxes and concealed links go through the fork's `CodeEditorTapInterceptor` (built in `modern_editor_wrapper.dart`): the tap is claimed at tap-down inside the editor's gesture pipeline, so the caret never moves, focus is never requested (no keyboard rise on an unfocused editor), and re-taps on the same spot fire every time. The zone rules themselves are the pure `EditorInputPolicy.resolveTap` (`lib/utils/editor_input_policy.dart`, table-tested row by row in `test/utils/editor_input_policy_test.dart` — a new rule goes there, never into the wrapper; `toggledTaskLine`, `listIndent` and the `GhostEngagement` two-tap state machine live beside it), and the wrapper maps the returned `EditorTapAction` to haptics plus the page callback. Zones resolve from line text via the shared grammars once at tap-down (`_claimTapAction` memoises a `_TapClaim`); tap-up (`_consumeTapAction`) reuses the memo when index/offset/line text/selection/fence flag are unchanged, re-resolves otherwise, and always drops it — never let a claim outlive its press. Zones in precedence order: checkbox, link, wiki link (`onOpenWikiLink`, the raw `[[title]]`), money, tag (`onOpenTag`, `#` preserved). Pass-through rules (keep ALL of them): reveal (selection-covered) lines — since 2026-10-19 a line reveals only while the editor has focus or a find session is active, and a revealed line keeps its task-box zone unless the collapsed caret sits inside the marker, see the dated paragraph at the end, fence lines, lines over `MarkdownEditorSpanBuilder.maxStyledLineLength`, taps clamped to the line-end offset (blank space), link-construct boundary offsets, escaped/image opens, brackets inside inline-code runs, and **ghosts win** — taps inside a ghost run ride the selection change. Desktop: primary-button only, shift-click passes through, claims are per-pointer, and the outer `ensureInput` is suppressed for claimed taps. One claim is live at a time (2026-09-04, Session 7b): a press arriving while a claim is live is never intercepted and takes the plain path, and on desktop the claiming pointer moving past the slop releases the claim into an ordinary drag selection — the fork replays the tap-down at the original down offset first, so the replay produces the caret and pairing state a plain press there would have produced (a down cell inside an existing selection takes `_selectPosition`'s `_handleByNextEvent` early return and the drag extends from that selection, exactly as a plain press does). Three rules from the 2026-09-05 review: the slop test is **per axis** through `computeHitSlop(kind, MediaQuery.maybeGestureSettingsOf(context))` (the private `_withinHitSlop`) at both the move-release rule and `_finishInterceptedTap`, so a claimed press either fires or becomes a drag exactly where the drag recognizers accept — a euclidean test leaves a sub-pixel diagonal window that releases the claim, moves the caret and fires nothing; a stranded claim (its pointer's up/cancel never reached the `Listener` — capture steal, `PointerRemovedEvent`) is dropped by the next primary press from the same mouse device (`_interceptedTapDevice`); and both deferred `Future(ensureInput)` sites are `mounted`-guarded. `test/re_editor/tap_interceptor_test.dart` (Android path) and `tap_interceptor_desktop_test.dart` pin all of it. Screen readers reach the same zones (Session 7c): `EditorInputPolicy.zonesOf` is the range-enumerating sibling of `resolveTap` (grammar-driven, first-claim-wins per offset in the same precedence, ghost runs cut out; the agreement group in `editor_input_policy_test.dart` pins that every offset resolves identically through both), the wrapper maps each zone's action to one of the five ARB labels (`editorZoneToggleTask` / `editorZoneOpenLink` / `editorZoneOpenWikiLink` / `editorZoneOpenMoney` / `editorZoneSearchTag`, resolved once in `didChangeDependencies`) and hands them to the fork through the interceptor's `zonesOf`. That path runs once per visible line on every semantics flush, so the wrapper answers the three pass-through rules first and memoises the rest per line text (`LruCache`, 256, dropped when the enabled-zone set or any label changes; `debugZoneResolveCount` counts misses) — and the fork's `set semanticsZonesOf` never sees the app's function (`CodeEditor` forwards its own bound method), so an app-side cache must invalidate itself. Zone node ids are keyed by line index: an edit that shifts a zone's line renumbers its node, an accepted TalkBack focus-continuity cost. The render's `onDidGainAccessibilityFocus` is plumbed on macOS only (2026-09-05 review, mirroring `material/text_field.dart` — on Android a TalkBack sweep would take keyboard focus that no lose handler gives back). `test/widgets/modern_editor_wrapper_semantics_test.dart` pins that activating a node toggles the box / opens the link / searches the tag with the caret untouched. A box tap toggles as **one atomic value change with the selection untouched**.
- Ghost taps are modal: the first tap selects the whole run (typing replaces), a second tap on the same unmodified ghost leaves the collapsed caret in place for in-place editing (engagement state clears when the selection leaves the run or the line's text changes; since the 2026-09-05 Session 6 review one arming feeds exactly one caret change — `GhostEngagement._engage` disarms on every bail-out, so a keyboard caret move inside the 350 ms window can no longer select a run — and a collapsed caret parked exactly on a run boundary disengages, matching `containsStrict`). `EditorInputPolicy.listIndent` snaps to the fork's two-column grid exactly like `_applyTextIndent`/`_applyTextOutdent` (so single-line and multi-line Tab agree), derives its unit from `MarkdownListUtils.indentUnit`, and both the wrapper's Tab and `EditorEditTracker`'s Enter continuation pass through on fence lines (`isFenceLine`); Enter with the caret parked right after a list marker splits the item (`- item` → `- `, `- item`) instead of deleting the marker line, and the Enter shape is tested before the paste threshold so a 20-space-deep item still continues. Ordered lists are not renumbered on Enter/Tab and ordered items never take a task box — both deliberate, documented on `getListPrefix` and `MarkdownListSyntax`.

**2026-10-19 — the quality-of-life pass (`docs/editor-qol-review-2026-10-19.md`; the sentences above that say "selection-covered" are superseded here).** **Reveal:** `MarkdownEditorSpanBuilder.revealsLine(focused:, findActive:, selection:, index:)` is `selectionCoversLine && (focused || findActive)`; the builder reads focus from `bindFocus(FocusNode?)` and the find state from `bindRevealWhenUnfocused(ValueListenable<bool>?)` (both forwarded by `EditorRenderController`; unbound means focused, so a host that binds nothing keeps the old behaviour — the note editor page and both event sheets bind their focus nodes, the page also binds `_findActive` from `_searchController.isSearching`, because the fork applies a find match as the selection only while the editor is unfocused and the match had to stay visible inside concealed syntax); `selectionCoversLine` runs before the focus walk so uncovered lines never pay it; the wrapper reads the same inputs (`widget.focusNode.hasFocus`, `revealWhenUnfocused`) for `resolveTap`, `zonesOf` and the tap claim (`_TapClaim.revealEnabled`), and rebuilds the `CodeEditor` subtree through a `ListenableBuilder` on the focus node because the fork's `_CodeEditable._onFocusChanged` never called `setState`; the render's `hasFocus` setter marks layout. **The box on the caret line:** `taskMarkerRevealed(item, caretOffset)` is true only for a range selection or a collapsed caret inside the marker, the half-open `[indent, contentStart)` — so `- [ ] |` right after an Enter continuation already paints the box and the first typed letter moves nothing; otherwise `_buildListItem` paints the `EditorCheckboxSpan` exactly as off-caret while the content after it stays revealed, reveal lines still bypass the memo and get the indeterminate state, and `resolveTap`/`zonesOf` (both take `caretOffset`) keep only the box zone on a revealed line; the caret line skips the wrapper's zone memo, the repeat-flush semantics test therefore expects one resolve, not zero (`test/widgets/modern_editor_wrapper_focus_reveal_test.dart`, the policy table's caret rows, the units suite's three-state corpus loop). **Taps:** a tap below the last line parks the caret at the document end and fires no zone (fork, `calculateTextPosition`). **Enter** (`EditorEditTracker` over `MarkdownListUtils.continuationPrefix` / `emptyLineEnd`): a quote or callout body continues with its `>` run as written (`> a` → `> `, `> > a` → `> > `, `> - a` → `> - `, a callout lead opens its body `> `); an empty line with a marker takes one marker back per Enter, innermost first — a nested item outdents one level through `EditorInputPolicy.listIndent(outdent: true)` (the same column as Shift-Tab), a top-level item ends into its quote or into a bare line, an empty quote run loses its innermost `>`; a callout lead is never empty; the edit is still the Enter's own undo node; `lib/pages/shortcut_editor_page.dart` runs the same helpers. **Backspace** right after a marker removes it in one keystroke as one undo step (`MarkerBackspacePolicy`, applied by `ListAwarePasteController` on both the hardware and the soft-keyboard path — the fork facts are in `fork-and-hot-path.md`). **The bar** (`MarkdownBar`): `onIndent`/`onOutdent` (`UtilityButtonId.indent`/`outdent`, right after undo/redo for new installs, appended to stored lists; hidden, not disabled, when a host wires nothing) run `ListIndentAction.apply` under the page's tracker guard, the same helper the wrapper's Tab uses; the H menu is `FormMenuChoiceItem`s with the ARB `header1…6` labels, `requestFocus: false`, the caret line's level checked (`currentHeadingLevel`) and `SemanticsIds.editorHeadingLevel(level)`; `hapticsEnabled` and the wrapper's flag come from `EditorSettings.hapticFeedback`; the normal row stays laid out but hidden under the suggestion bar (`Visibility` maintained size + `Positioned.fill`, built once as the builder's `child`), the B/I/H glyphs no longer scale with text size and the pills clamp to 1.4, so the bar keeps one height with or without a session; buttons ink on a transparent `Material`; default shortcut tooltips come from ARB keys by id. **Shortcut semantics** (`ShortcutApplier`): `rewrites`/`applyRewrite` run before any `await` — `toggleLinePrefix` (the `linePrefix` insert type on the default list, task, numbered and quote ids however they were persisted; whole caret line or every selected line, after the indentation and after a quote's `>` run; same kind removes, another list kind swaps, numbered continues the nearest non-blank ordered item above; fence lines left alone through the optional `isFenceLine`), `toggleWrap` (unwrap when the selection is `**x**` or the markers sit immediately outside both ends — for `*`/`_` only against non-word characters, and for a collapsed caret only when the pair is empty; the inner text stays selected; an empty selection inserts the pair with the caret between; symmetric custom wrappers toggle too, an accepted consequence), `applyHeaderLevel` (exact level, same level removes, caret column kept; `applyHeader` still cycles); Ctrl/Cmd+B/I on desktop reach the page through the wrapper's `onFormatShortcut` and run under the same guard as the bar.
