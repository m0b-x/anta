## Vocabulary Autocomplete (v32)
User-defined term lists that the editor offers while typing, so the same exercise stops being written three different ways. **Nothing it inserts is new syntax** — an accepted suggestion is plain text, which is why existing notes, every markdown construct, exports and the preview pipeline are all untouched by this feature. Design record: `docs/vocabulary-autocomplete-feature.md`.

- **Data**: `vocabularies` (name, `is_enabled`, `sort_order`) + `vocabulary_items` (`vocabulary_id`, `term`, `sort_order`), both carrying the five CRDT columns **from birth** (the v29 template shape — no `DEFAULT ''`, nothing to backfill). Terms are rows, not a delimited blob, because any delimiter is a term someone eventually types ("Squat, paused") and because per-row identity is what survives a re-save. The column is `term`, not `text` — `text()` is Drift's column builder and a getter of that name would shadow it. **No index**: both tables load wholesale into the facade at first use, the v29 reasoning.
- **`;;` lines are section headers**, stored as ordinary `vocabulary_items` rows so they carry position and identity exactly like terms — the diff-based save reorders and tombstones them with no special case, and a list round-trips through the editor unchanged. Only the suggestion path filters them (`Vocabulary.suggestibleItems`, consumed by `Vocabularies.updateCache`); the grammar lives on `VocabularyItem` (`commentMarker`, `isCommentText`, `commentLabel`) because that is the one file both the facade and the service already import, so neither depends on the other. Two characters, not one, so a term keeping a single semicolon is never swallowed. Headers de-duplicate like any other line, and **"how many terms" always means `Vocabulary.termCount`**, which excludes them.
- **The list editor is a page (`lib/pages/vocabulary_editor_page.dart`), not a bottom sheet.** A sheet is capped at a fraction of the screen *and* gets no keyboard padding from the framework, so a long list showed a handful of lines and the only way to see its shape was to dismiss the keyboard. A `Scaffold` resizes for the keyboard itself — hence **no `viewInsets` arithmetic anywhere in that page**, unlike every sheet in the app. The name field and enable switch fold away while the terms field has focus (the header chevron re-opens them without dismissing the keyboard), so the list gets the whole body.
- **`VocabularyDao.saveItems` is a diff, never a wipe-and-reinsert.** The editor edits the whole list as one block, so every save re-submits every term; wiping would fork each row's id and bump each version, turning one edited word into a full-list conflict once devices merge. Unchanged terms keep their row and version, removals **tombstone**, and a re-added term resurrects the row it had before. Re-saving an untouched list issues no writes at all.
- **`VocabularyService`** is the `EventTemplateService` shape (whole table loaded once, republished after every mutation, `forTesting`, `DatabaseLifecycle` reset clearing singleton **and** facade). It owns term normalization: `parseTerms` trims, drops blanks and de-duplicates **folded**, so "Bench press" typed twice in different case collapses to the first spelling. Store verbatim, match folded — the tag roadmap's canonicalization rule.
- **`Vocabularies` (lib/constants)** is the synchronous facade the editor reads per keystroke: `candidates` is the flattened, pre-folded candidate list of *enabled* lists only (folding happens once per publish, never per keystroke), and `byName` resolves a ghost placeholder to a list with singular/plural tolerance in both directions. `idsForScopeTokens` is the trigger-side resolver and is deliberately looser — folded **prefix** match (`@exer:` → "Exercises", `@push:` → "Push Day") *or* the same plural tolerance — returning a **set**, because one token naming several lists is a feature and not an ambiguity to reject.
- **Two entry points, one session** (`VocabularySuggestionController`, lib/controllers): a **trigger character** (`SettingsKeys.vocabularyTriggerChar`, default `@`) typed after whitespace, and an **engaged ghost** — the wrapper already selects a tapped `{{ … }}` run whole, so the controller reads that straight off the selection and needs **no coupling to `ModernEditorWrapper`'s tap state at all**. **Either entry point can scope itself to particular lists.** A named placeholder (`{{exercise}}`) scopes to that list; on the trigger side, everything before the run's **first colon** is a comma-separated scope segment — `@exercise:ben` filters inside Exercises, `@exercises,meals:oat` inside the union of the two, `@ben` is unchanged and searches everything. Splitting the *run* (not the line) keeps prose colons (`sets: @ben`) out of it. **Resolution is allowed to fail and never blocks typing**: a scope naming no list falls back to an unscoped query over the raw run *as written*, colon included, and an omitted one (`@:ben`) is an unscoped query for what follows. Accepting consumes the whole run, scope included. The one unreachable shape is `:` configured as the *trigger*: the separating colon is then a mid-word trigger occurrence and the guard protecting `a@b.com` fires first — do not widen that guard to recover it. Once the user types over the engaged run the braces are gone, so the ghost's start offset is kept as an **anchor** and the session keeps filtering from there; a second space, a caret move before it, or a non-collapsed selection abandons it.
- **`VocabularyTrigger` (lib/utils)** owns the "is the caret in a query" rule — a *typing* grammar, never persisted, rendered or exported, which is why neither render surface consumes it. The trigger needs whitespace before it and a non-space after, so `3x8 @ 60kg`, `5x5@100kg` and `a@b.com` all stay ordinary text; it returns null inside a ghost run (ghosts win, as everywhere else). Callers add the editor-state guards it cannot see: collapsed selection, not composing, not a fence line, under `maxStyledLineLength`.
- **`VocabularyMatcher` (lib/utils)** ranks prefix > word-start > substring > subsequence, folding through `normalizeForSearch` (never a second fold table), capped at 8, with the user's own list order as the tie-break inside every tier. Bucketed rather than sorted, so input order survives and a full prefix tier short-circuits the scan. Its `vocabularyIds` filter is a set: `null` unscoped, an **empty set matches nothing** — a caller whose scope resolved to nothing decides upstream (where the raw run is still available) rather than silently searching everything.
- **The bar replaces the toolbar's content at identical height** (`VocabularySuggestionBar`, branched inside `MarkdownBar.build` behind a `ValueListenableBuilder` so only the bar rebuilds) — 40px pills inside 8px padding, matching the shortcut row exactly. A session opening must never shift the editor; capture speed is the whole point, and a jumping toolbar would cost more than the autocomplete saves. It stays inside the existing `CodeEditorTapRegion`, or tapping a pill would drop the keyboard. A scoped session labels itself with the resolved list names ahead of the pills, inside that same height budget — user data, so no l10n key.
- **Accepting** replaces `[start, end)` through the page's `_applyVocabularyInsertion`, which carries the full programmatic-insert discipline (`_isProcessingTextChange` guard, one `runRevocableOp` so a completion is a single undo step, `_previousTextLength` resync) — the `_handleShortcut` contract. A trailing space is added only when the next character is not already one, so end-of-line accepts keep typing flowing while `{{exercise}} 3x8` keeps its spacing.
- **re_editor's own `CodeAutocomplete` is deliberately unused** even though the fork ships it intact: it hijacks Enter and the arrow keys while open (which breaks "never block free typing"), anchors a popup at the caret rather than at the thumb, matches prefix-only, and does not wrap its insertion in `runRevocableOp`. No fork change was needed for this feature.
- **Not shipped, on purpose**: no render-time highlighting of known terms (it would touch the span builder's perf-critical memos and both render surfaces), no per-term insertion templates, no usage learning, no per-note/folder binding. `candidateSource` on the controller is the seam the tag roadmap's Tier 2.4 `#tag` autocomplete and the `/` slash-menu idea plug into — same session, bar and insertion path, different provider.
