## From "Single-source-of-truth grammars (never fork them)"

- `MarkdownInlineGrammar` (`lib/utils/markdown_inline_grammar.dart`) — the inline tokenizer (2026-09-04): a pure function of `text.substring(start, end)` plus the line's ghost runs, reading nothing outside the range, so the preview's substrings and the editor's ranges agree by construction. Atoms first (escape unless it would escape a ghost's `{{`; ghost; backtick code span closed by a run of exactly the same length — unclosed runs are literal), then `[[title]]` wiki links (2026-09-06, Session 9: probed on a doubled `[` before the link rule so `[[` wins at one offset, rejected when any atom would start inside the construct — a ghost, escape or code span between the brackets leaves the whole thing literal — and the title is **literal**, never a nested range: it is the note-title lookup key, so `[[**a**]]`, `[[#tag]]`, `[[https://x]]` are wiki links with raw titles; `[[a|b]]` is literal, `[[a]]]` is a wiki link plus `]`, `![[a]]` is `!` plus a wiki link on both surfaces), links/images, `{name:text}`, `#tag`, bare URLs, and delimiter runs of `*` `_` `~~` `==` paired like CommonMark's delimiter stack (nearest same-char opener, rule of three, openers spend from the end of the run and closers from the start, three-on-three is one bold-italic token, `~~`/`==` two at a time). Only top-level tokens come back; consumers recurse into `InlineEmphasis.contentStart..innerEnd`, link text and colour inner ranges with `depth + 1`, and past `maxNestingDepth` (8) the tokenizer returns only the range's ghost runs (placeholders are never styling, so a ghost stays concealed on both surfaces at any depth), so both surfaces flatten identically. Pairing carries CommonMark's `openers_bottom` bound (lazily allocated, 24 slots) — keep it, a 4 k-char line of unpairable runs is otherwise quadratic on every keystroke — and a bare URL gives a trailing `*` `_` `~` back to the emphasis around it (GFM; `=` never). Code spans and wiki-link titles are literal all the way down. Open debt (Session 4 review, 2026-09-05): a `{` or `}` inside a code span inside `{name:…}` still kills the colour run on both surfaces because `MarkdownColorSyntax._findClose` is atom-blind. Tests: `test/utils/markdown_inline_grammar_test.dart` (tokens) + the agreement suite.
- `MarkdownLineShape` (`lib/utils/markdown_line_shape.dart`) — line shapes: `headingAt` (1–6 `#` + space or line end after optional indent; `###` alone is an empty heading, `#tag` is not), `isHorizontalRule`, `isTableRow` / `isTableSeparator` (the table-row shape — leading/trailing blanks allowed, `|` at both ends, at least two units; the separator is a row of dashes/colons — owned here since 2026-09-05, the preview's `_MarkdownPatterns` copies are gone, and the editor's tables-lite branch reads the same two), `isLineLedConstruct` (the paste policies' one predicate: quote/callout, table row, fence delimiter, horizontal rule — added 2026-09-05, a `---` used to be six lines after a narrow paste — ATX heading, and money rows incl. list-prefixed ones via probe+parse). Preview, editor and `MarkdownLineHeightCalculator` all call these — never re-scan hashes or rule markers.
- `MarkdownCalloutSyntax` (`lib/utils/markdown_callout_syntax.dart`) — `> [!TIP]`-style callouts (types: note, tip, important, warning, caution, success, pr) and, since 2026-09-05, the quote grammar too: `isBlockquoteLine` (allocation-free, byte-identical to the `trimLeft` form — ASCII whitespace inline, non-ASCII through the fallback), `blockStep(line, open)` — the ONE per-line transition of the callout block scan (lead opens, every following blockquote line continues with the same type, a nested lead is body of the outer block, a blank/non-quote line ends it; fences are the caller's business), consumed by `MarkdownChunker._scanBlocks` and by `MarkdownEditorLineIndex`'s positional callout pass so the preview block and the editor roles have one extent by construction — and `quoteMarkers(line) -> MarkdownQuoteShape?` (`depth`, `markerOffsets`, `contentStart`; each `>` may carry one space; non-null exactly when `isBlockquoteLine`), the nested-quote shape both surfaces render bars from. Never re-scan `>` markers by hand.
- `MarkdownTagSyntax` (`lib/utils/markdown_tag_syntax.dart`) — `#tag` scanning (Unicode-aware, letter-led, word-boundary rules), shared by preview renderer and editor span builder. Tags render tinted; both surfaces route a tag tap to global search with `#` preserved by `normalizeForSearch` — the editor through `ModernEditorWrapper.onOpenTag` (a tap zone with the link zone's pass-through rules: caret/reveal line, fences, >4096, ghosts win) feeding the page's `_handleTagTap`. `TagIndex` roadmap is in the tag roadmap doc.

Four shape-only composable chrome layers (**all compose on one line**: `- ## **$= teal: 500**`; order is list marker → heading → emphasis wrapper → `$`): an **emphasis wrapper** — 1–3 uniform `*` or `_` tight against the `$` with a matching closer (same char/length) at the line end, trailing spaces allowed (`*$~ 2 Change: $ *`); A resolved token tints the **whole row incl. the label** (`labelStyle`, colour only — base weight kept); the label takes the row accent either way, so a token-less op row still colours its label with the semantic sign colour. Plus a **value slot**: a lone space-delimited `$` in the label (`$$ Current sum: $`, `$+ 12.50 now $`) renders the row's computed value there instead of its default position, so text can precede the number while the marker stays line-led. Scanned by `_scanValueSlot` **only from inside `parse`**, never from the probes, so non-money lines pay nothing; display-only (balances are identical with and without slots); it moves any row onto the editor's positional path (gate: `valueSlot >= 0 || total/delta/diff/span`) and the label's `$` becomes the 1:1 paint placeholder — keep any marker substitution one code unit wide (`Δ=`/`Δ~` narrow to `Δ`) or the caret drifts. `$=` shows a value only via a slot. Balances are derived from content — never persisted, never mutate counters. Fence lines are inert and the 4096 `maxLineLength` guard matches the editor's raw-render guard so the two ledgers agree. Amounts max 11 int digits / 2 decimals (factors 4/4); a well-formed amount past a limit (or `$/ 0`) parses as an **error row** — yellow (`MarkdownConstants.moneyWarning`), fold-inert *including the history/anchor appends* (all three folds guard with `hasError`), source-preserving on both surfaces (editor substitutes `$`→`!` 1:1, never replaces text), message via the shared `errorMessage()`. Balances clamp at ±999,999,999,999.99 via split multiply/divide (exact under 2^53); a value pinned at the cap (`valuePinned()`) renders in the warning colour everywhere. Palette: `MarkdownConstants.moneyPositive/moneyNegative/moneyNeutral/moneyWarning`. A `$=` row's amount renders **as a value** (`formatCentsWithSymbol`, so the currency shows) — its operand *is* its value, hence no trailing annotation — and `$! N` declarations share the rule; every other row keeps its operand raw and carries the currency on the computed value. The currency may be typed inline after the amount (`$= 500 lei`) — `inlineCurrencyEnd`/`labelStartAfterCurrency` match it **only against the note's configured symbol**, whole-word and ASCII-case-insensitively, display-only (both spellings fold identically); preview and sheet drop it, the editor keeps it visible as typed. Label-first rows allow **free trailing text** after the amount (`$= Net worth: 5000 lei as of today`; `$!` targets take the shape too): `_scanTrailingAmount` walks candidates right-to-left and the LAST whole token that parses as an amount directly behind a `:` wins — deterministic, never guessed — with a digit`:`digit tight-colon guard so times/ratios (`9:30`, `2024:500`) are skipped (this also fixed the old line-end quirk where `$= Standup 9:30` set 30). - `MarkdownColorSyntax` / `MarkdownColorPalette` (`lib/utils/markdown_color_syntax.dart`) — colour grammar + palette, shared by the preview and the editor span builder. `{name:text}` colours text; `==name:text==` tints a highlight (plain `==text==` keeps the legacy amber, which *is* the `yellow` preset). Names are lowercase `[a-z0-9_-]` (≤24); **an unresolved name is never consumed**, so `{note:x}` and `==note: x==` keep their source text. Presets are light/dark pairs; custom colours (settings, `SettingsKeys.markdownCustomColors`, `name=aarrggbb;…`) shadow presets and are contrast-resolved **once at palette construction** — render time is one map probe, never contrast maths per span. The palette is value-equal on its persisted `source`, which is what makes it a valid render-cache key; thread it exactly like the money config (BOTH `prepareWithStyle` call sites + `configureColors` on the editor builder, which clears both span memos). Editor rendering is pure conceal (`{name:` / `}` transparent + ~0 size — no substitution, no code-unit change). Ghosts win: the editor's ghost-skip branch must **fall through** for a non-ghost `{`, or coloured text stops rendering on every line containing a ghost. See COPILOT_CONTEXT.md "Markdown Colors".
- `MarkdownLinkPatterns` (`lib/utils/markdown_link_patterns.dart`) — link grammar: `bareUrl` / `matchBareUrlEnd` (GFM trailing-punctuation trim — since the 2026-09-05 Session 4 review that includes `*` `_` `~`, so `*https://a.com*` gives its closer back to the emphasis; `=` is never trimmed, base64 padding in query strings is real) and `matchInlineLinkAt` (`[text](url)` construct), shared by preview renderer, paste line-breaker, and — through `MarkdownInlineGrammar`, which decides where a link may sit — the editor span builder and the wrapper's tap zones. Editor `[text](url)` links conceal `[` + `](url)` off-caret; tapping a concealed link opens it via the page's scheme-validated opener, while bare URLs stay tap-to-edit (fully visible source). `![image](url)` stays raw in the editor (an `InlineLink` with `isImage`; the preview renders `!` + link). Since 2026-09-06 (Session 9) the module also owns `[[title]]` wiki links: `matchWikiLinkAt` / `MarkdownWikiLink` (the title is the run up to the first `]`, may hold no `[` `]` `|` CR LF and at least one non-blank unit, the closing `]]` must sit inside the limit, and the scan never reads past it) plus the `wikiLink` RegExp the paste width line-breaker protects from being split (a deliberately wider shape, never a render or tap rule). The editor conceals `[[` and `]]` off-caret and paints the title in the link-text style; the preview drops the brackets; both are tappable through `InlineWikiLink` — `EditorOpenWikiLinkAction` carries the raw title, the page trims it and resolves through `NoteStorageService.resolveNoteByTitle` (one statement on the v36 `idx_notes_ltitle`: `LOWER(TRIM(title)) = LOWER(?)`, ASCII case-insensitive, tombstones out, the current folder preferred, else the newest `updatedAt`), then saves the position and pushes the editor; a miss shows the neutral `wikiLinkNoteNotFound` snackbar (no auto-create, no muted "unresolved" style — the render path never touches the database), a link to the open note itself does nothing, and two rapid taps push one editor (the handler bails once the page is no longer the current route). No alias, autocomplete, backlinks or rename propagation.
