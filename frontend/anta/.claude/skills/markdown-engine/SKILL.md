# Markdown Engine & Editor

Related docs: [docs/markdown-feature-ideas.md](../../../docs/markdown-feature-ideas.md) (candidate features + fit analysis), [docs/tag-system-roadmap.md](../../../docs/tag-system-roadmap.md) (tag feature plan), and [docs/live-markdown-editor-roadmap.md](../../../docs/live-markdown-editor-roadmap.md) (live editor rendering — status, decision log, remaining gaps). The full invariant list lives in [COPILOT_CONTEXT.md](../../../COPILOT_CONTEXT.md) sections "Markdown Preview Pipeline", "Markdown Block Model And Chunking", "Markdown Lists", and "Ghost Text".

## The one hard constraint

**Every rendered span keeps its exact source offset.** The recursive inline parser (`_parseInline`) routes every leaf text run through `_applyHighlighting` with its exact source offset so search highlights and editor↔preview scroll mapping survive nested emphasis, links, escaping, ghosts, tags, and lists. When adding inline syntax, never break this offset threading.

**One inline grammar.** `_parseInline` (preview) and `EditorInlineEmitter.append` (editor) are emitters over `MarkdownInlineGrammar.tokenize` — neither scans for emphasis, code, escapes, links, colours, tags, URLs or ghosts itself, and the wrapper's tap zones resolve through `MarkdownInlineGrammar.linkAt`/`tagAt`, which are themselves the offset form of `linksAndTags` (the whole-line walker over the same tokenizer and the same descent: `linkAt`/`tagAt` return the first `InlineLink`/`InlineTag` whose `containsStrict` holds, and `EditorInputPolicy.zonesOf` takes the whole list) — one descent, so the two forms cannot disagree; pass the line's ghost runs in when you already have them. A new inline construct is added to the tokenizer (one token class, one placement rule) and then emitted by both surfaces; the agreement suite `test/utils/markdown_inline_agreement_test.dart` fails when only one surface changes. Headings and horizontal rules come from `MarkdownLineShape.headingAt` / `isHorizontalRule` everywhere.

## Preview pipeline layering (keep intact)

Deprecated since 2026-09-03: gated by `SettingsKeys.previewModeEnabled` (default off, under Settings → "Deprecated features"). The page's `_canPreview` (`previewModeEnabled || !liveMarkdownRendering`) decides whether the preview can exist at all and `_showPreview` (computed once per build) whether it is the visible surface right now — gate new preview-touching code on those two, never on `_isPreviewMode` directly. When `_canPreview` is false nothing below mounts or runs.

```
OptimizedNoteEditorPage
  -> MarkdownPreviewBloc -> MarkdownRenderService -> LineBasedMarkdownBuilder
       -> MarkdownChunker (block scan + chunk layout)
       -> MarkdownListSyntax (shared list grammar)
  -> MarkdownPreviewBlocView -> SourceMappedMarkdownView
```

- Bloc state is `Equatable`, primitives + `renderHandle: int` only. **Never put `InlineSpan` trees or builders in state** — widgets pull spans from `bloc.renderService.builder` on demand; heavy rebuilds are gated by `buildWhen` on `renderHandle` / `linesPerChunk` / `fontSize`.
- Content sync: `bloc.bindContentProvider(() => controller.text)` once in `initState`; `bloc.markContentDirty()` per keystroke; dispatch `PreviewContentRefreshRequested` for lazy/debounced refresh (500 ms, gated on `!_isLoading` and `state.hasTheme`); `PreviewContentChanged` only for eager pushes (toggle, checkbox, locale change, load). Never dispatch from `build()`.
- Theme dispatch (`PreviewThemeChanged`) only from `MarkdownPreviewBlocView` lifecycle hooks — never `build()`. Scroll progress bypasses the event queue via `bloc.scrollController.updateProgress(progress)`.
- Search sync: call `_searchController.updateContent(content)` from `_pushPreviewContent` / `_scheduleLivePreviewRefresh` when searching — never from `build()`.
- `MarkdownPreviewBlocView` binds its own `GlobalKey<SourceMappedMarkdownViewState>` into the bloc's scroll controller on mount (reusing one already bound, so a remount keeps targeting the live state); the page holds no preview key of its own (2026-09-04) and reads `scrollController.currentLineIndex` — never an inline anonymous key on the view.
- Chunks are **block-aligned with variable line counts** — never compute `lineIndex ~/ linesPerChunk`; use `chunkStartLine(i)`, `chunkIndexForLine(line)`, `MarkdownRenderService.chunkStartLineForLine(line)`.
- Toolbar: reuse `_buildMarkdownBar({required bool enabled})` for both loading and loaded paths — never duplicate the `MarkdownBar(...)` tree.
- Preview links: validate schemes (`http`, `https`, `mailto`, `tel`) before `launchUrl` in `LaunchMode.externalApplication`; localized errors via `CustomSnackbar.showError`.

## Single-source-of-truth grammars (never fork them)

- `MarkdownInlineGrammar` (`lib/utils/markdown_inline_grammar.dart`) — the inline tokenizer (2026-09-04): a pure function of `text.substring(start, end)` plus the line's ghost runs, reading nothing outside the range, so the preview's substrings and the editor's ranges agree by construction. Atoms first (escape unless it would escape a ghost's `{{`; ghost; backtick code span closed by a run of exactly the same length — unclosed runs are literal), then links/images, `{name:text}`, `#tag`, bare URLs, and delimiter runs of `*` `_` `~~` `==` paired like CommonMark's delimiter stack (nearest same-char opener, rule of three, openers spend from the end of the run and closers from the start, three-on-three is one bold-italic token, `~~`/`==` two at a time). Only top-level tokens come back; consumers recurse into `InlineEmphasis.contentStart..innerEnd`, link text and colour inner ranges with `depth + 1`, and past `maxNestingDepth` (8) the tokenizer returns only the range's ghost runs (placeholders are never styling, so a ghost stays concealed on both surfaces at any depth), so both surfaces flatten identically. Pairing carries CommonMark's `openers_bottom` bound (lazily allocated, 24 slots) — keep it, a 4 k-char line of unpairable runs is otherwise quadratic on every keystroke — and a bare URL gives a trailing `*` `_` `~` back to the emphasis around it (GFM; `=` never). Code spans are literal all the way down. Open debt (Session 4 review, 2026-09-05): a `{` or `}` inside a code span inside `{name:…}` still kills the colour run on both surfaces because `MarkdownColorSyntax._findClose` is atom-blind. Tests: `test/utils/markdown_inline_grammar_test.dart` (tokens) + the agreement suite.
- `MarkdownLineShape` (`lib/utils/markdown_line_shape.dart`) — line shapes: `headingAt` (1–6 `#` + space or line end after optional indent; `###` alone is an empty heading, `#tag` is not), `isHorizontalRule`, `isLineLedConstruct` (paste policies). Preview, editor and `MarkdownLineHeightCalculator` all call these — never re-scan hashes or rule markers.
- `MarkdownChunker` (`lib/utils/markdown_chunker.dart`) — block model + chunk layout, shared by preview and the editor debug overlay. Multi-line blocks only (code fences, callouts); single-line content is implicit. New single-widget block types set `atomic: true`.
- `MarkdownListSyntax` (`lib/utils/markdown_list_syntax.dart`) — list grammar shared by editor (`MarkdownListUtils`: Enter-continuation, Tab/Shift-Tab) and renderer. **Never reintroduce a second list regex** — extend `MarkdownListSyntax`.
- `GhostText` (`lib/utils/ghost_text.dart`) — `{{ … }}` placeholder scanning, consumed by preview renderer, editor span builder, tap handling, and the `default_ghost` shortcut. Markers are concealed in the editor (transparent + ~0 width) so caret offsets never desync; tapping selects the run, nothing is mutated.
- `MarkdownCalloutSyntax` (`lib/utils/markdown_callout_syntax.dart`) — `> [!TIP]`-style callouts (types: note, tip, important, warning, caution, success, pr).
- `MarkdownTagSyntax` (`lib/utils/markdown_tag_syntax.dart`) — `#tag` scanning (Unicode-aware, letter-led, word-boundary rules), shared by preview renderer and editor span builder. Tags render tinted; both surfaces route a tag tap to global search with `#` preserved by `normalizeForSearch` — the editor through `ModernEditorWrapper.onOpenTag` (a tap zone with the link zone's pass-through rules: caret/reveal line, fences, >4096, ghosts win) feeding the page's `_handleTagTap`. `TagIndex` roadmap is in the tag roadmap doc.

- `MarkdownColorSyntax` / `MarkdownColorPalette` (`lib/utils/markdown_color_syntax.dart`) — colour grammar + palette, shared by the preview and the editor span builder. `{name:text}` colours text; `==name:text==` tints a highlight (plain `==text==` keeps the legacy amber, which *is* the `yellow` preset). Names are lowercase `[a-z0-9_-]` (≤24); **an unresolved name is never consumed**, so `{note:x}` and `==note: x==` keep their source text. Presets are light/dark pairs; custom colours (settings, `SettingsKeys.markdownCustomColors`, `name=aarrggbb;…`) shadow presets and are contrast-resolved **once at palette construction** — render time is one map probe, never contrast maths per span. The palette is value-equal on its persisted `source`, which is what makes it a valid render-cache key; thread it exactly like the money config (BOTH `prepareWithStyle` call sites + `configureColors` on the editor builder, which clears both span memos). Editor rendering is pure conceal (`{name:` / `}` transparent + ~0 size — no substitution, no code-unit change). Ghosts win: the editor's ghost-skip branch must **fall through** for a non-ghost `{`, or coloured text stops rendering on every line containing a ghost. See COPILOT_CONTEXT.md "Markdown Colors".
- `MarkdownLinkPatterns` (`lib/utils/markdown_link_patterns.dart`) — link grammar: `bareUrl` / `matchBareUrlEnd` (GFM trailing-punctuation trim — since the 2026-09-05 Session 4 review that includes `*` `_` `~`, so `*https://a.com*` gives its closer back to the emphasis; `=` is never trimmed, base64 padding in query strings is real) and `matchInlineLinkAt` (`[text](url)` construct), shared by preview renderer, paste line-breaker, and — through `MarkdownInlineGrammar`, which decides where a link may sit — the editor span builder and the wrapper's tap zones. Editor `[text](url)` links conceal `[` + `](url)` off-caret; tapping a concealed link opens it via the page's scheme-validated opener, while bare URLs stay tap-to-edit (fully visible source). `![image](url)` stays raw in the editor (an `InlineLink` with `isImage`; the preview renders `!` + link).
- `MarkdownConstants.calloutAccent` — per-type callout accent palette (light/dark), shared by the preview's callout rendering and the editor's lead-line bar + `[!TYPE]` token tint.

## Live editor rendering (`lib/utils/markdown_editor_span_builder.dart`)

`MarkdownEditorSpanBuilder` renders essential markdown *inside* the re_editor text mode, gated by the "live markdown rendering" editor setting (`SettingsKeys.liveMarkdownRendering`, default true; OFF = plain text + ghost-only rendering). Routing lives in `EditorRenderController.buildSpan` (`lib/controllers/editor_render_controller.dart`, page-owned; it also holds the render-context cache, the money config and the palette, and reports whether `applyMoneyConfig`/`applyPalette` changed anything so the page repaints only then): markdown builder first, the static `ghostSpan` fallback. The renderer is **six libraries, one responsibility each** (2026-09-04) and callers import `markdown_editor_span_builder.dart` alone: the builder itself owns `build()`'s routing and the line shapes (header / quote / rule / list item / fence); `editor_render_context.dart` holds `EditorRenderContext` (style, baseColor, primary, isDark, onAccent) — **no `BuildContext` exists anywhere under `lib/utils/markdown_editor_*`**, the page resolves one context per theme/style generation through `EditorRenderContextCache` and hands the same instance to every line, and that context is the span memos' generation key (adopting an unequal one drops them); `markdown_editor_span_cache.dart` owns the text-keyed LRU (1024), the positional LRU (128), the money parse memo (256) and `adoptContext`; `markdown_editor_emitter.dart` (`EditorSpanEmitter`) turns a source range into leaves — ghost split, `concealStyle`/`dimStyle`, `emitChrome`, and the debug code-unit inventory assert; `markdown_editor_inline_emitter.dart` (`EditorInlineEmitter.append`) emits `MarkdownInlineGrammar` tokens and owns the inline styles; `markdown_editor_money_row.dart` (`EditorMoneyRowBuilder.build`) builds the money row; `markdown_editor_paint_spans.dart` holds `EditorMoneyTotalSpan` / `EditorCheckboxSpan` / `EditorCheckboxVisual`. The emitters are **static** — the build path allocates no emitter and captures no closure per line. Invariants:

- **Code-unit preservation** — the returned span always contains exactly the source line's UTF-16 code units. Markers are concealed (transparent + ~0.01 fontSize) or substituted 1:1 (`-`→`•`, `[`→MaterialIcons check glyph); never insert or remove characters, or caret/selection/search offsets desync.
- **Span memo LRU** — built spans are cached per line text and returned as identical instances; the cache is cleared when the `EditorRenderContext` generation changes (style / baseColor / primary / isDark) and **must only be consulted after the fence check** (fence status is positional, not textual). Reveal (caret/selection) lines bypass the cache.
- **Caret-line reveal** — lines covered by the selection show raw dimmed markers; only marker conceal/substitution may differ between reveal states, never line height (no vertical layout shift on caret moves).
- **Ghosts compose** — ghost regions are opaque to the inline scanner (no run opens or closes inside one) and all content is emitted through the ghost-aware `_emit`. Grammar comes from `MarkdownListSyntax` / `GhostText` — never fork them.
- Tappable checkboxes and concealed links go through the fork's `CodeEditorTapInterceptor` (built in `modern_editor_wrapper.dart`): the tap is claimed at tap-down inside the editor's gesture pipeline, so the caret never moves, focus is never requested (no keyboard rise on an unfocused editor), and re-taps on the same spot fire every time. The zone rules themselves are the pure `EditorInputPolicy.resolveTap` (`lib/utils/editor_input_policy.dart`, table-tested row by row in `test/utils/editor_input_policy_test.dart` — a new rule goes there, never into the wrapper; `toggledTaskLine`, `listIndent` and the `GhostEngagement` two-tap state machine live beside it), and the wrapper maps the returned `EditorTapAction` to haptics plus the page callback. Zones resolve from line text via the shared grammars once at tap-down (`_claimTapAction` memoises a `_TapClaim`); tap-up (`_consumeTapAction`) reuses the memo when index/offset/line text/selection/fence flag are unchanged, re-resolves otherwise, and always drops it — never let a claim outlive its press. Zones in precedence order: checkbox, link, money, tag (`onOpenTag`, `#` preserved). Pass-through rules (keep ALL of them): reveal (selection-covered) lines, fence lines, lines over `MarkdownEditorSpanBuilder.maxStyledLineLength`, taps clamped to the line-end offset (blank space), link-construct boundary offsets, escaped/image opens, brackets inside inline-code runs, and **ghosts win** — taps inside a ghost run ride the selection change. Desktop: primary-button only, shift-click passes through, claims are per-pointer, and the outer `ensureInput` is suppressed for claimed taps. One claim is live at a time (2026-09-04, Session 7b): a press arriving while a claim is live is never intercepted and takes the plain path, and on desktop the claiming pointer moving past the slop releases the claim into an ordinary drag selection — the fork replays the tap-down at the original down offset first, so the replay produces the caret and pairing state a plain press there would have produced (a down cell inside an existing selection takes `_selectPosition`'s `_handleByNextEvent` early return and the drag extends from that selection, exactly as a plain press does). Three rules from the 2026-09-05 review: the slop test is **per axis** through `computeHitSlop(kind, MediaQuery.maybeGestureSettingsOf(context))` (the private `_withinHitSlop`) at both the move-release rule and `_finishInterceptedTap`, so a claimed press either fires or becomes a drag exactly where the drag recognizers accept — a euclidean test leaves a sub-pixel diagonal window that releases the claim, moves the caret and fires nothing; a stranded claim (its pointer's up/cancel never reached the `Listener` — capture steal, `PointerRemovedEvent`) is dropped by the next primary press from the same mouse device (`_interceptedTapDevice`); and both deferred `Future(ensureInput)` sites are `mounted`-guarded. `test/re_editor/tap_interceptor_test.dart` (Android path) and `tap_interceptor_desktop_test.dart` pin all of it. Screen readers reach the same zones (Session 7c): `EditorInputPolicy.zonesOf` is the range-enumerating sibling of `resolveTap` (grammar-driven, first-claim-wins per offset in the same precedence, ghost runs cut out; the agreement group in `editor_input_policy_test.dart` pins that every offset resolves identically through both), the wrapper maps each zone's action to one of the four ARB labels (`editorZoneToggleTask` / `editorZoneOpenLink` / `editorZoneOpenMoney` / `editorZoneSearchTag`, resolved once in `didChangeDependencies`) and hands them to the fork through the interceptor's `zonesOf`. That path runs once per visible line on every semantics flush, so the wrapper answers the three pass-through rules first and memoises the rest per line text (`LruCache`, 256, dropped when the enabled-zone set or any label changes; `debugZoneResolveCount` counts misses) — and the fork's `set semanticsZonesOf` never sees the app's function (`CodeEditor` forwards its own bound method), so an app-side cache must invalidate itself. Zone node ids are keyed by line index: an edit that shifts a zone's line renumbers its node, an accepted TalkBack focus-continuity cost. The render's `onDidGainAccessibilityFocus` is plumbed on macOS only (2026-09-05 review, mirroring `material/text_field.dart` — on Android a TalkBack sweep would take keyboard focus that no lose handler gives back). `test/widgets/modern_editor_wrapper_semantics_test.dart` pins that activating a node toggles the box / opens the link / searches the tag with the caret untouched. A box tap toggles as **one atomic value change with the selection untouched**.
- List lines with content return a `CodeHangingTextSpan` root (fork class): the paragraph provider lays out the marker prefix and content as two paragraphs so wrapped lines get a hanging indent. Never change a line's code units to achieve indent; the hanging span only tags the root.
- Ghost taps are modal: the first tap selects the whole run (typing replaces), a second tap on the same unmodified ghost leaves the collapsed caret in place for in-place editing (engagement state clears when the selection leaves the run or the line's text changes).
