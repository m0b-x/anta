Reference, not rules — moved verbatim from the calendar-ui SKILL.md on 2026-11-11. The rules stayed there; the source of truth for an id is `lib/constants/semantics_ids.dart`. Read only the surface you touch: the first bullet is one long run ordered by the date each family arrived (grep the surface's prefix), the next bullets are the filter surfaces, the categories page and the settings pages.

A dynamic helper spells its argument the way a flow can: a date as `yyyy-MM-dd` (`{{day+N}}`), a hex lower-cased. A form sheet's drag surface is `excludeFromSemantics: true` (`FormSheetFrame` — its drag callbacks otherwise read as a scrollable) and a sheet whose root is a `Focus` (the time pad) sets `includeSemantics: false` so the header's title stays its own node. **A new row in the editor gets an id in the same change**, and the flow that walks its screen (`tool/qa/flows/calendar/`) is updated in the same slice.
- **Titles are not targets on the calendar page**: every marked day cell's marker label carries its events' titles, so a row is addressed by `id:event-row-<eventId>`. Day cells themselves can carry no id (`table_calendar` wraps them with excluded semantics); a flow taps a day by its label, `{{longdate+N}}`.
