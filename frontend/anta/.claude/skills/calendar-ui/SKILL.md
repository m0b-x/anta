# Calendar UI

Every calendar surface speaks the app's UI language, and the calendar is where it was set (the 2026-09-25 event editor redesign — [docs/event-editor-redesign-roadmap.md](../../../docs/event-editor-redesign-roadmap.md) §2–§3 holds the owner's decisions D1–D20 and the token spec). **The rulebook is the `ui-language` skill; load it first.** The idioms, the row primitives, the sheet chrome, the metrics and the tests every surface ships with are there. This skill holds only what is the calendar's own.

**Adoption.** `docs/calendar-language-adoption-roadmap.md` (2026-09-27, the owner's max-effort plan for every calendar surface still outside the language, four tiers) is being worked, and the drive-by rule of `ui-language` is suspended while it runs: read it before touching any calendar sheet or page, and update its §9 status table per tier. §9 is also where to read which calendar surfaces speak the language today.

## Shared pieces

- **`EventAvatar(icon:, color:)`** — radius 20, icon 24, background at α 0.16. The colour follows `EventSummaryProvider.colorFor` (the custom colour only while `tintIcon`, else the category colour). The **bar** rule (`colorValue ?? category`) is a different thing and belongs to grid bars, rails and stripes.
- **`AgendaPeriodNav`** — chevron | title + count | a fixed 48 dp today slot | chevron. `onTitleTap` makes the title a control (drop-down glyph) and is called with the title's own context: the day list opens `MonthYearPickerSheet` with it, the overview its Period menu through `showFormMenu` anchored to that context (2026-10-14). Null callbacks disable; the fixed slot is what keeps the title from shifting. The title may take two lines (`FormMetrics.periodTitleMaxLines`) in a box as tall as the tallest title the row will show — pass `month:` on a month nav so the box is measured over that year's twelve titles and paging never moves the grid; a year nav passes nothing. The twelve are laid out once per key and kept in a static `LruCache` (`yearTitleCacheSize`) keyed on every input of their layout, so a rebuild lays out only the shown title — a new input to that layout joins the key. The count is a semantics node of its own and shrinks to fit one line inside a box of its one-line height, never cut and never taller. `previousIdentifier` / `nextIdentifier` / `todayIdentifier` / `titleIdentifier` are optional ids, set only where a flow walks the nav (the day list's `day-list-nav-*`).
- **`YearMonthTile` + `MonthDotMatrix`** — the year overview's tiles, shared by the drill-down and the Dates sheet's year view. `YearMonthTile.gridDelegate` is the grid; `dayColors` paints per-day colours, `missedMask` / `dayMissedAlpha` fade missed days. One `Semantics` node per tile, the matrix excluded. Since 2026-10-15 the overview's Year mode draws them in `AgendaYearScroll` (one section per year under a flat 48 dp `_YearHeader`: the year at 22 / 500, the count at the right in the caption role, blank while unresolved; `OverviewListMetrics.yearHeaderHeight` measured once per text scale, `yearSectionGap` 16) and the day list sheet in `AgendaYearPager`; both through `AgendaYearTileBuilder`.
- **Day grids** render `CalendarDayCell` + `CalendarDayBars`, never table_calendar's own decorations. Dates go through `CalendarDatePickerSheet`, times through `TimePadSheet`, categories through `CategoryPickerSheet`, month/year through `MonthYearPickerSheet` — never `showDatePicker` or `showTimePicker`.

- **Titles are not targets on the calendar page**: every marked day cell's marker label carries its events' titles, so a row is addressed by `id:event-row-<eventId>`. Day cells themselves can carry no id (`table_calendar` wraps them with excluded semantics); a flow taps a day by its label, `{{longdate+N}}`.
- The filter surfaces' ids: `filter-…` on the sheet, `filter-list-…` on the check list, `category-pick-…` on the picker, `filter-preset-…` on the presets (its name dialog's field and Save `filter-preset-name` / `filter-preset-name-save` since 2026-10-13, shared with the overview's saved views), `calendar-filter-open` / `calendar-saved-filters-open` on the bar.
